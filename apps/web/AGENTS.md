# Web (`@hub/web`)

React 19 SPA built with Vite. In dev, `/trpc` is proxied to the server (`vite.config.ts`). Two layouts: `/desk` (4K dashboard) and `/deck` (iPhone X PWA, 375x812, no scroll, dark).

Notes about one module live in `AGENTS.md` inside that module's folder (`src/modules/<name>/` and the folders named below). Read the one for every module you touch.

`src/modules/devices/`, `src/components/ui/`, `src/modules/media/`, `src/modules/pomodoro/`, `src/shell/`, `src/modules/audio/`, `src/theme/`, `src/settings/`, `src/modules/system/`, `src/modules/music/`, `src/modules/sites/`, `src/modules/jobs/`, `src/modules/study/`, `src/modules/notes/`, `src/modules/calendar/`.

## Desk layers and scrolling

- The desk content scroller (`shell/desk.tsx`) is `relative` on purpose: it is the containing block of every absolutely placed node in a page (the `sr-only` live regions of steppers, rows, inspector). Without it they were placed against the body and a long page grew a second, document-level scrollbar (step 33, guarded in `settings.spec.ts`).
- The desk has no visible title row: `shell/desk.tsx` renders an `sr-only` h1 and the `ActivityBall`. The ball starts top left and can be dragged; the rail centres below `ball-clear`. Fill zones own their scroll regions: pass height through flex children with `min-h-0`, and give lists `min-h-0 flex-1 overflow-y-auto overscroll-contain` with the bottom gutter inside.

- Plain desk pages scroll the inner scroller of `PageSurface`; the rounded outer frame clips its native scrollbar (default width, owner 2026-11-17). Its opaque sticky band holds the tabs and optional page controls. Fill pages with independent panes keep their own scroll regions. Impostazioni action rows remain sticky within their own pane; a sticky element lasts only as long as its parent, and the side aside sticks below the actions.

- **Scroll rules (2026-11-17).** One scroller per pane: the window never scrolls, each pane owns at most one `overflow-y-auto` and nothing between the shell and it scrolls (`min-h-0` / `min-w-0` on every flex or grid child of that chain, or the wrong box scrolls). Padding goes inside the scroller, so the scrollbar sits on the edge; spacing between blocks comes from the parent's `gap`, never from a child's outer margin, so paddings do not add up through nested panels. Headers and tabs are `sticky` inside the scroller, not above it. Every desk scrollbar takes `scrollbar-color: var(--muted-foreground) transparent` from the one rule in `index.css` (an opaque track drew a dark stripe on surfaces); do not set it per element. A rounded scroller clips its scrollbar only through `clip-path` on its frame (see `shell/AGENTS.md`). To find a stray scroller, the Elements panel of Chrome DevTools marks each scroll container with a "scroll" badge.

## Where files go

```

  routes/      file routes only: compose shell and module components, no logic of their own
  shell/       the frame around modules: desk.tsx (DeskShell), rail, zones.ts, zone-page.tsx, zone-sections.ts, widgets.ts, widget-board.tsx (Panoramica), command-palette.tsx, header-slot.tsx, backdrop, activity (the ball), deck-frame, pages.ts, deck-pages.tsx, use-layout
  theme/       theme.tsx (ThemeProvider), themes.ts, contrast.ts (+ test), theme-panel.tsx (Aspetto picker and editor)
  lib/         trpc.ts, auth.ts, auth-link.ts, use-now.ts, widget-size.ts, zone-search.ts: client plumbing used everywhere
  components/  flat list of shared primitives (panel, tile, registry-button, zone-tabs, page-grid); ui/ = Hairline sources
  modules/<name>/  everything one module shows: desk-panel.tsx, deck-tile.tsx, use-<name>.ts, its provider
```

- `lib/day.ts` (`localDay`, `addDays`, `dayDate`) and `lib/parse-day.ts` (`parseDay(text, today, direction)`: the words for the past read the same either way; a bare weekday or a year-less date is the next one in `future`, the last one in `past`) are shared by Post-it and catalog modules.

- A file used by one module lives in that module. It moves to `components/` (UI) or `lib/` (logic) only when a second module uses it. `shell/` never holds module content.
- Flat: at most two folder levels under `src/` (`modules/pomodoro/desk-panel.tsx`); `components/ui/` is the only deeper folder. No folder per component.
- A small piece used by one component stays in that component's file; it gets its own file in the module when a second file needs it or the file passes about 250 lines. No abstraction for later.
- No `index.ts` barrels: import from the defining file. One main export per file, file named after its role in kebab case (`desk-panel.tsx`, `deck-tile.tsx`); hooks are `use-*.ts`. Exported names stay descriptive (`PomodoroPanel`).

## Routing: TanStack Router (file-based)

- Routes are files in `src/routes/` (`__root.tsx`, `index.tsx` redirects to `/desk`, `desk.tsx` (layout), `desk.index.tsx` (Panoramica), `desk.{studio,media,system,devices,settings,lavoro,messaggi}.tsx` (zone pages) and `desk.$module.tsx` (module zones), `deck.tsx`). The Vite plugin regenerates `src/routeTree.gen.ts` in dev and build, `tsr generate` does it before typecheck. It is committed but never edited by hand, and excluded from lint and Prettier.
- Every zone route sets `validateSearch: zoneSearch` (`lib/zone-search.ts`): a zod schema, `z.object({ tab: z.string().optional().catch(undefined) })`, that the router runs as a Standard Schema (`router-core` `validateSearch()` calls `~standard.validate` and fails the whole route on an issue, so a value that is not a string is dropped with `.catch`, never rejected; `?tab=3` arrives as a number). Pages with filters extend it. `/desk/$module` sets `zoneSearch.loose()`: `validateSearch` gets only the query, never the `$module` param, so the generic route cannot pick a module schema and must keep unknown keys; each module validates its own with `zoneSearch.extend` and `.catch` on every field. `zod` is a dependency of the web app at the server's version (one copy in the lockfile); use it for URL state, not for tRPC (those types come from the server).
- Web schemas import `z` from `src/lib/zod-csp.ts`, which configures `z.config({ jitless: true })` before any schema builds so Zod v4 skips its `new Function("")` probe under `@fastify/helmet`'s strict `script-src 'self'` CSP.
- In `vite.config.ts` the router plugin must stay before `react()`, or generation and code splitting fail silently.
- Each layout route calls `useLayout('desk' | 'deck')`, which sets `html[data-layout]`; layout-wide CSS (the desk root size) keys off that attribute.

## Data: tRPC + TanStack Query

- `src/lib/trpc.ts` exports `TRPCProvider` and `useTRPC` from `@trpc/tanstack-react-query`.
- Use the options proxy with plain TanStack Query hooks: `useQuery(trpc.health.queryOptions())`, `useMutation(trpc.x.mutationOptions())`. Invalidate with `queryClient.invalidateQueries({ queryKey: trpc.x.queryKey() })`.
- Do not wrap these in custom hooks unless the wrapper adds real logic (combining queries, a shared derived shape). Forwarding options is not logic.
- Types come from the server router. Never redeclare a server type by hand; infer it (`inferRouterOutputs<AppRouter>`) if you need it outside a hook.
- Live state comes from the server's subscriptions: `useSubscription(trpc.x.onState.subscriptionOptions())` (from `@trpc/tanstack-react-query`). `data` is `undefined` until the first push and survives reconnects (only `idle` clears it), which is what lets tiles show the last known state. No `refetchInterval`, and stateful module controls do not invalidate queries: the server pushes the new state. The generic palette dispatcher invalidates cached queries after a successful action because layout and device administration also have query-only state. The `state` queries stay on the server for tests and LLM tools; the web app does not call them.
- Links (`src/main.tsx`): `splitLink` sends subscriptions over `wsLink({ client: wsClient })` and everything else over `httpBatchLink`. `wsClient` lives in `src/lib/trpc.ts`, its URL is built from `location` (so the Vite proxy in dev and the LAN later both work), and the browser sends the page origin with the upgrade: the server refuses any origin not on its allowlist. In dev the page must be on `http://localhost:5173` or `http://127.0.0.1:5173`, or its origin must be in the server config (`server.allowedOrigins`), for example when Vite moves to another port.
- **Auth**: `src/lib/auth.ts` keeps the device token in `localStorage` (`hub.token`, `useToken()` with `useSyncExternalStore`). HTTP sends it as `Authorization: Bearer` (`headers` on `httpBatchLink`), the socket as `connectionParams` (a function, read on every connect). The server decides who a socket is once, when it connects, so `replaceToken(token | null)` in `src/lib/trpc.ts` closes `wsClient` first and the next subscription opens a new one with the new token; use it, never `setToken` alone. `authLink` (constructed in `src/lib/trpc.ts` via pure `createAuthLink` in `src/lib/auth-link.ts`, first link) turns any `UNAUTHORIZED` answer, from a query, a mutation or a subscription, into `replaceToken(null)`: a revoked or unknown token lands on the pairing screen. A wrong pairing code is `BAD_REQUEST`, on purpose, so it never looks like a lost token.
- `useConnectionLost()` (`src/lib/trpc.ts`, `useSyncExternalStore` over `wsClient.connectionState`) is true when the state is `connecting` with an error, that is the socket closed or failed and the client is retrying; the first attempt has no error and is not "lost". The deck header swaps its status for `connection_lost` and tiles get `stale`. The page recovers by itself when the server comes back, no reload.
- `null` is a real answer (`media.state` with no player); `undefined` data means not loaded yet. Check `=== undefined`, not falsiness.

## Styling: Tailwind v4 + design tokens

- **One rule for the two faces (owner, 2026-11-17):** JetBrains Mono only for figures that change: `text-readout` (a large figure: clock, timer, percentages, counts) and `text-figure` (a small one: a unit, the day line's hours, the status line, Studio's step numbers). Every label, title and state, machine ones included, is Urbanist: `text-caps` (small capitals) or the type roles. Code the owner reads or copies (a command, a JSON setting) is `text-code`. `lint:tokens` fails on a hand-written `font-mono` outside `components/ui/`. The boards of step 68 drew labels in mono; the owner found the mix incoherent once built ("robe slegate"), so the rule replaced them. `Ticks` represents discrete counts, not continuous progress.

- Never key a rule on a theme name (`[data-theme='paper'] .x`); add a variable instead.
- Theme changes glide: the color variables are registered with `@property` (`<color>`, end of `index.css`) and `html` transitions them over `--motion-standard`, so the browser interpolates every color and a change in mid-glide starts from the current one.
- A new color variable used by themes must be registered there too. Hover previews start after the pointer rests 200 ms on a card.
- `rounded-panel` does not exist (radii are sm..xl); a wrong radius name compiles to nothing.
- Tailwind `max-w-md` resolves to this project’s 1rem spacing token, so use named width tokens such as `max-w-dialog-md` for forms.
- Tailwind v4 adds `content` to `after:` itself: the token guard rejects `after:content-['']` and `aria-[...]` variants, use a conditional class.

Tailwind v4 through `@tailwindcss/vite`, no config file. All tokens live in `src/index.css`, with the reasoning for each scale in comments there. Tailwind's default scales are switched off (`--spacing: initial`, `--text-*: initial`...), so only named steps exist and an off-scale value does not compile.

- **Spacing** (4px base, rem): `3xs 2xs xs sm md lg xl 2xl 3xl 4xl`, chosen by relationship, not by eye: `xs` icon to label, `sm` rows of a list, `md` deck tile padding and related items, `lg` desk panel padding and gap between panels, `xl` between sections, `2xl`+ page margins. Fixed boxes: `touch` (44px minimum target), `icon-sm`, `icon`, `icon-lg`.
- **Type roles**, each with its own line height, tracking and weight: `text-caption`, `text-label`, `text-body`, `text-title`, `text-heading`, `text-display`, `text-hero` (major third scale). Pick a role; never set `leading-*`, `tracking-*` or `font-*` weight by hand to fake a new one. Numbers that change use `tabular-nums`.
- **Radii** `sm md lg xl full`: a shape inside another steps down one level so corners stay concentric (panel `xl`, card inside `lg`, control inside `md`).
- **Colors** only through semantic tokens with shadcn names (`bg-background`, `bg-surface`, `text-muted-foreground`, `border-border`, `bg-primary`, `text-accent`...). Themes are value sets on `[data-theme]`; see "Themes".
- **Desk scaling**: `html[data-layout="desk"]` raises the root font size to 150% for the 3840px viewport at scale 1; everything is in rem, so the whole system scales together. Tune that one number after looking at the real monitor, never individual sizes.
- **No arbitrary values**: `p-[13px]`, `text-[#fff]` and friends are rejected by `pnpm --filter @hub/web lint:tokens` (part of `pnpm lint`). A missing value becomes a new token with a reason, not a one-off. The vendored shadcn/Hairline components in `src/components/ui/` are excluded from the guard; map their sizes onto these tokens.
- **Private modules and Tailwind.** Source detection covers `apps/web` only, so `index.css` names the private root with an `@source` (a discovery point, see the root `AGENTS.md`); without it a utility used only by a private module's `ui.tsx` generates no CSS and fails silently (`w-touch` squeezed the Lavoro icon buttons to their icon until 16g2). A clone without the folder builds unchanged. <!-- guard-private: allow Repository-local module directory -->
- Font: Urbanist (variable, OFL, self-hosted via `@fontsource-variable/urbanist`), provisional until the font decision in the design doc is closed.
- Third-party notices: `vite build` writes `dist/third-party-licenses.md` (served at `/third-party-licenses.md`) from exactly the packages in the bundle (`build.license` in `vite.config.ts`, with license texts). Vite skips code outside `node_modules` and packages that arrive only through CSS, so `extraNotices` in the same file appends the Urbanist OFL and the vendored Hairline MIT; a new self-hosted font, CSS-only package or vendored source goes in that list. `rough-notation` (0.5.1, exact, MIT, for the Lavoro detail marks) is collected by the build, but it ships `roughjs` inlined, which the bundler does not see: its notice is `third-party/roughjs-LICENSE`, listed in `extraNotices`.
- Components come from Hairline UI via the shadcn CLI (`npx shadcn@latest add https://hairlineui.com/r/<name>.json`). Generated component code is ours to edit.

## Aesthetic

- Mono for figures only (see Styling); Urbanist for everything else. Never invent a metric.

- Neutrals only, one theme accent for active state and the main figure; other color comes from cover art and photos. Keep the font, Urbanist, and a few weight roles; main figures are large and light.
- Borders are low-opacity 1px hairlines; separators inside panels are dashed. Panels use large radii, nested shapes step down one radius, controls/nav/filters/badges/player are pills. Lots of air and few elements per panel.
- Nav and player float above content and may overlap a panel edge. Only those layers use `.desk-glass`: translucent surface, backdrop blur and hairline, on every theme (70% light glass in paper); Vetro off makes it solid. Panels stay `bg-surface`. Media backdrop uses blurred/darkened cover art; other zones use a quiet radial gradient (tinted by the accent in light themes).
- Charts are greyscale, with the current value solid or in the accent. Do not invent metrics or player features the server cannot provide.
- State changes get short, purposeful motion: selection slides, labels reveal, numbers roll, icons morph. Nothing loops without purpose; the rail's connection dot pings while connected, stopping on disconnection/reduced motion (`shell/rail.tsx`). Reduced motion makes transitions instant, including WAAPI icon transitions.
- Every UI step compares its new baselines with the hub references by eye and writes one comparison line per screen in its plan Progress, stating what matches and what deliberately differs.

## Hairline components

- Inside a modal `<dialog>` it portals into that dialog, chosen in `show` before it mounts: a surface on the body sits under the top layer, so no z-index lifts it (the Lavoro detail tooltips were hidden behind the dialog). `Popover` still portals to the body, so one opened inside a dialog would hide the same way.

- Vendored MIT sources and LICENSE live in `src/components/ui/`. Install via the shadcn CLI and the local `components.json`, preview with --dry-run/--diff, target src/components/ui and inspect dependencies first. Never let the CLI replace our tokens. Preserve upstream notices; generated code must pass the same types/lint/format/privacy checks as app code.
  - Never use a native `<datalist>`: Chromium on Wayland opens it as a separate window at the screen edge, full height. Lavoro's rule value field has its own small combobox list instead (`ui-rules.tsx`, `ValueField`).
  - `components/chip.tsx` (`Chip`): the house removable tag, a `Badge` plus a focusable remove button named by Paraglide `chip_remove`; Backspace and Delete on it remove. No registry item fits.
- Only `src/components/ui/` is excluded from the arbitrary-class guard, alongside generated Paraglide. That also means nothing flags a stock Tailwind step there: with `--spacing: initial`, `h-5`, `size-4` or `pt-8` compile to no CSS and lint stays green (the vendored `slider.tsx` rendered a 0px track until 2026-11-08). Map every size to a token or an explicit arbitrary rem value when vendoring. Map visible spacing/type/colors to named tokens; upstream geometry/keyframes/timings can stay. Keyframes used through inline animation names must survive Tailwind compilation. Components are ours to adapt for semantics and accessibility; no broad lint exceptions.
- `components/registry-button.tsx` supplies Italian action labels and accessible names to ActionButton; it uses async mutations so pending/success/error represent the actual request. `data-status` exposes the current feedback state; `pressed` forwards `aria-pressed` for an icon toggle. A failure is handled by the component, not an unhandled rejection. Keep non-action navigation buttons separate.
- Counts that change in place use `NumberRoll`; it shows in-flow digits at rest and the strip only during a roll, including reduced motion. Mount it only once the first real count is known.
- A NumberRoll rolls when its value changes, so it must mount with the first real value: the desk timer renders its digits only once the subscription has data (an invisible `timer.time` holds the space until then). Fed a 0 placeholder, it rolled in from 00:00 on every visit to Studio. The same goes for a tab `count` (`ZoneTabs`): pass it only once it is known.

## Deck tiles

- `src/components/tile.tsx` (`Tile`) is the one deck control: a `<button>` with `aria-label` `"<label>: <state>"` (plus `, <status>` when the optional `status` prop is set: read by screen readers, not shown, for a fact the icon alone carries), an icon (`@phosphor-icons/react`, exported `Icon` type, `size-icon`, `aria-hidden`), a `text-label` label and a `text-caption` state clamped to 2 lines (a tile is ~105px wide at 375px). `pending` disables and dims it; `stale` (the live connection is down) dims it with `opacity-60` and keeps the last state; `error` swaps the state line for `tile_error` in the danger color until the next tap.
- Deck pages use one tile size and rows at least 6.5rem high; short visible volume labels retain their longer accessible names. The player stays below both pages.
- A specific tile owns its state subscription and its mutation and lives in its module folder (`modules/audio/deck-tile.tsx`, `modules/media/deck-tile.tsx`), not in `src/routes/`: every file there becomes a route. `shell/pages.ts` places them on deck pages.
- Loading and unreachable-server copy is generic (`tile_loading` until the first push, `tile_unavailable` when there is no data and the connection is lost); the media tile icon shows the action a tap performs (Pause while playing), and its text is `artist - title` whatever the play state; the play state is the `status` prop (`media_playing`, `media_paused`, `media_stopped`), so the accessible name is `Musica: Artist - Title, in pausa` and e2e locates by role and name. Tile sets stable `data-icon` and `data-weight` hooks on its SVG; media uses `play`/`pause`. Never assert SVG path data.
- Phosphor icons use canonical `*Icon` exports and `regular` by default; `fill` means on/active only in a two-state control. Size through token classes, not numeric `size` props (the library defaults to `1em` SVG attributes). Tile takes `iconName` and `iconWeight`; the Luci bulb keeps one glyph with `regular` off and `fill` on.
- Output labels on the audio tile are values from the user's server config, not Paraglide copy.
- Tapping an action tile against the real server changes the user's audio or playback. Verify taps with the fake server (`pnpm test:e2e`, see `apps/e2e/AGENTS.md`), and take screenshots without tapping. A change to a tile, a layout or a token is covered by `apps/e2e` specs and baselines: the screenshot test fails on any pixel change, so update the baseline only when the change is intended.

## No magic values

- Sizes, spacing, radii, colors, durations and font sizes come from theme tokens or the Tailwind scale, never inline literals. If a value is missing, add a token in `src/index.css` and reuse it; a per-file `const SIZE = 24` is a second source of truth that drifts.
- Before building a component, check `src/components/` (and Hairline UI) for one to reuse or extend.

## Conventions

- Never put a path or any unbreakable string in a `flex` row without `min-w-0`: it pushed the `ml-auto` button over the next column (step 43b).
- `TextMorph` duplicates button text, so e2e reads `aria-label`, not `toHaveText`.
- Do not flip a button's `type` between `button` and `submit` on click (React flips it before the default action, the click then submits): render two elements.
- a hook returned as an object must use arrow properties (`setView: (v) => ...`) or the type-aware lint flags the destructured method as unbound.

- `lib/use-now.ts` (`useNow(target | 'clock' | null, offset?)`) is the one clock: a `useSyncExternalStore` whose snapshot is the second on screen, with a timeout per caller on the next whole second of the time left (or of the clock); `null` schedules nothing. Never tick with `setInterval` or read `Date.now()` in render.

- Function components and named exports.
- Relative imports keep the `.tsx`/`.ts` extension, like the server.
- Touch targets on the deck at least 44px; icon-only buttons carry an accessible label (`aria-label`). Every action button shows pending, done and error states.
- Destructive actions use `components/hold-button.tsx` (`HoldButton`), never a single tap: a wrapper over Hairline `hold-to-confirm` with 800 ms, Italian labels and hint (the vendored component got a `hint` prop for it), an accessible name that says it needs a hold. Its `onConfirm` passes `confirmed: true`, which the server requires for every `danger` mutation (`devices.revoke`, `theme.delete`, `system.suspend/reboot/powerOff`). `outline` gives the quiet pill for a row of several (the power actions); the vendored component got `variant` for it and `min-h-touch` in place of an `h-11` that the token scale does not compile. On the deck the same hold is `components/hold-tile.tsx` (`HoldTile`): tile shape, ring around the icon, built on the vendored `useHoldConfirm`.
- **React Compiler is on** (`vite.config.ts`: `@rolldown/plugin-babel` with `reactCompilerPreset`, Babel 7). No hand-written `useMemo`, `useCallback` or `memo`; if one is truly needed, a comment says why. Vendored Hairline files keep theirs as shipped. `HUB_COMPILER_LOG=1 pnpm --filter @hub/web build` lists components the compiler skips, with the reason (a disabled React lint rule, a `try` with `finally` or without `catch`, a computed object key, a ternary inside a logical test); run it instead of trusting a list here (on 2026-11-16 it named 19 public files, ten of them in `components/ui/`, plus private ones). A skipped component runs uncompiled and correctly. Babel must stay on 7: with Babel 8 the compiler 1.0 skips every component that has a default value in its props. Never read the DOM or other outside state during render (computed styles, sizes, `Date.now()`): the compiler memoizes it and it goes stale. Read it with `useSyncExternalStore` (the widget board's grid metrics are the example).
- **Effects only synchronize with something outside React** (the DOM outside the component, timers, sockets, `localStorage`, `matchMedia`). A value computed from props or state is computed during render; a reaction to a user action happens in that event's handler, including updating a parent or a context (call its setter next to your own `setState`, never from an effect that watches your state). oxlint enforces the first two (`react/set-state-in-effect`, `react/no-deriving-state-in-effects`) but cannot see a context or prop setter called from an effect: that case is on review. A cleanup-only effect (reset on unmount) is fine. See react.dev "You Might Not Need an Effect".

## Desk zones and panels

- `PageSurface` `float` (tab `float: true`, through `ZonePage` and `ZoneTabs`): the surface does not clip (no `overflow-hidden`), its body does not scroll, and it leaves `mb-3xl` instead of `mb-xl`, so something can hang over its bottom edge. Musica has no spacer row: its floating player sits at the bottom; the ball starts by the rail, so the top right of the content is free. Used by Musica: `MusicPlayer` is `absolute -bottom-touch left-1/2 w-5/6 -translate-x-1/2` against the surface (the page root is a fragment, not `relative`), and the page columns keep `pb-2xl` so lists stay clear of the part of the pill inside the surface. Lists in a `float` page must scroll in their own box, since a `float` surface does not clip.
- Module zones whose page renders its own `ZoneTabs` (private Lavoro) set `zone.ownTabs`: `desk.$module.tsx` then gives the page only the fill frame and `ZoneTabs` draws the bar as the first row of the page's own surface. A page that draws a `PageSurface` without `ZoneTabs` (Lavoro's config error) gets no spacer either.
- The token guard rejects arbitrary values (`w-[86%]`, `grid-rows-[...]`): use fractions (`w-5/6`) and `grid-rows-1`.

- `shell/zones.ts` is the rail: Panoramica `/desk`, then the pages Studio `/desk/studio`, Media `/desk/media`, Sistema `/desk/system`, Dispositivi `/desk/devices`, then Lavoro `/desk/lavoro` and Messaggi `/desk/messaggi` only when a module adds a section to them (`work` and `messages` have no content of their own: no rail entry and a not-found page otherwise), then module zones (`/desk/$module`), and Impostazioni `/desk/settings` last. A module zone id is also its path segment: it must not be `lavoro`, `messaggi` or `settings`, which the built-in routes shadow. `routes/desk.tsx` renders `DeskShell`, which owns the rail, the `sr-only` h1 and Outlet; its `notFoundComponent` says "Pagina non trovata" inside the shell. Named desk-rail and desk-inset spacing tokens reserve a touch target, rail padding/border and content gutters; no arbitrary margin to clear the rail.
- Only Panoramica is a widget board ("Widgets"). Every other zone is a page with no edit mode (no "Modifica"): its route renders `ZonePage zone own` (`shell/zone-page.tsx`), which lists the page's own tabs (`PageTab`: id, label, component) followed by the sections modules aim at it (`shell/zone-sections.ts`, `pageTabs`) and renders them with `ZoneTabs`. A page with one tab shows no tab bar; the first tab is the default. A page with a single tab of its own labels it with the zone name, visible only once a section adds a second. Content is laid out plainly with `PageGrid` and `Panel`s (placeholders until each page's own design; the Media hero and its floating player stay at the top). The full panels (`PomodoroPanel`, `MediaPanel`, `AudioPanel`, `DevicesPanel`, `StatusPanel`, `ThemePanel`) are used as they are, and a widget that has no page panel (`controls`, `power`, Hue `lights`) is placed at its largest size: no second copy of a control.
- `components/zone-tabs.tsx` (`ZoneTabs({ tabs })`, tab = `{ id, label, count?, content }`) is the one tab component (WAI-ARIA tablist/tab/tabpanel, roving tabindex, Left/Right/Home/End, optional rolling count). The active tab is the `?tab=` search param (`/desk/devices?tab=luci`): `activeTab` falls back to the first for a missing or unknown value, `tabParam` leaves the first tab out of the URL, and a click replaces the history entry. Keys `1`-`9` switch zones, never tabs. A module page that needs tabs uses `ZoneTabs` itself; filters keep their URL state the same way, through `zoneSearch.extend` (see Routing).
- `components/animated-list.tsx` keeps departing rows in the DOM through exit: leave the `AnimatedRows` boundary mounted when its last item is removed, and mark exiting items inert and `aria-hidden`. Empty-list wrappers collapse at rest with the `notes-presence-*` CSS pattern. `AnimatedItem` forwards div props so row handlers remain attached; card-grid wrappers must keep their children stretched to the row height. `Crossfade` also retains its outgoing tab subtree; portal-backed `TabBarActions` and `TabBarRow` must render only for the present tab via `useIsPresent`, or both tabs can expose controls at once. `FadeImage` fades a wrapper so CSS opacity on the image remains effective; contrast helpers that composite cover art must multiply wrapper opacity by image opacity.
- **One page surface.** `PageSurface` (`data-page-surface`) is the single rounded frame for desk pages. Plain pages, including Panoramica and Lavoro, scroll its inner `data-page-scroller`, with a stable gutter and a default-width native scrollbar (owner chose it over `thin`, 2026-11-17) clipped by the frame. The tab bar and optional `TabBarRow` controls share an opaque sticky band, whose measured height sets scroll padding; tab changes reset the scroller. The tabpanel is the body and does not scroll. Multi-pane `fill` pages retain their own scrollers; Musica remains `float`. `TabBarActions` occupies the end of the tabs row.
- **Inner panels:** `Panel` reads `SurfaceContext` (`useInSurface`): inside a surface it is `rounded-lg bg-muted p-lg`, no border, `data-panel`; outside it keeps the old card. `bg-muted`, not `bg-surface-raised`: in paper `--surface-raised` is the dark contrast card. One level only: no panel in a panel (`zone-pages.spec.ts` checks `[data-panel] [data-panel]`, borders and panels outside a surface). A hand-made inner block that is not a `Panel` (study plan days, folder, inbox items) is `rounded-lg bg-muted p-lg` with `data-panel`. Sections of the same thing inside one panel are separated by dashed hairlines; a box inside an inner panel (pairing code, command line) is plain text, no box. Nothing hand-writes `rounded-xl border bg-surface` on a zone page.
- `components/panel.tsx` owns the shared surface/border/radius/padding and optional semantic h2/action row, with a unique heading id. Compact Pomodoro/Audio and Status panels (Panoramica) link to their zones.
- Keys 1-9 navigate desk zones in rail order. The handler ignores modifiers, repeats, prevented events and input, textarea, select and contenteditable targets; it is removed on unmount. No deck shortcuts were added.
- Paper hover must use a light neutral token such as muted: surface-raised is dark in paper and makes dark secondary text disappear. Active/inactive rail hover classes are separate for the same reason.

## Widgets (Panoramica)

- **One rule per size (step 67):** Piccolo (`3x1`) shows title and state on top, one large value with its caption bottom left, at most one control bottom right, and clicking outside a control opens the page; Medio (`6x1`) puts Piccolo on the left and the next action with its command on the right; Grande (`6x2`) shows a short list of at most six rows with one action per row plus a footer count of omitted items and the page link.
- A widget is `modules/<name>/widget.tsx` exporting a component that takes `size` and renders a variant per size, listed in `shell/widgets.ts` (or a module's `widgets` in `lib/modules.ts`) with its allowed sizes (the default layout is in `shell/widgets.ts`). A widget fills its cell (`h-full`) and the cell clips (no scrollbars on a widget); only the device list, the one content that grows, scrolls inside its own widget; small variants put the label on top and the one figure large at the bottom.
- Content inside a widget sizes from the cell, never from page-level tokens: the large Musica widget once used the hero cover (`media-cover`, up to 24rem) and pushed its title and transport out of the cell; it uses `Cover fill` (`modules/media/widget.tsx`) in a `min-h-0 flex-1` box. `widgets.spec.ts` checks the panel does not overflow.
- `components/split-pill.tsx` (`SplitPill`) is the one pattern for a button that splits into two actions and merges back (from the owner's marked reference "Confirm and cancel buttons that morph"); use it for any such pair instead of a new animation. The board's Modifica/Ripristina/Fine uses it. CSS `.split-pill` in index.css; the extra button stays mounted and `inert` so it can animate out.

## Module clients

- `createModuleClient` (`lib/module-client.ts`) builds a tRPC client of its own on the shared WebSocket. Every tRPC client counts its operation ids from 1 and the socket keys requests by id, so two clients collided: a module's subscription got an id the main client used and the server answered "Duplicate id". `lib/module-link.ts` moves each module client's ids into its own block (`module-link.test.ts`). Any new client sharing `wsClient` must go through it.
- `ModuleUI` (`lib/module-ui.ts`): `widgets` are for Panoramica; `todayItems` is a hook or list of hooks (`TodayLinesHook`, `(day: 'today' | 'tomorrow') => TodayLine[] | null`, step 66) that Oggi calls through one `LinesProbe` per hook and day, like the activity ball, so it can count every line and cut them by number per size (Medio 2, Largo 3, Grande 4, Esteso 6, then "e altre N"); each line renders as `components/today-row.tsx` (`TodayRow`: outline `Badge` chip, text with an optional muted tail, a value or "Apri", the whole row one link, or a dismiss button when it has no link). The probe's prop is `useLines`: under the React Compiler a hook passed as `hook` was skipped on some renders ("Cannot set properties of undefined (setting 'destroy')"). `records` is a `RecordSource` or a list (step 64, see `docs/modules.md`): the palette runs `useQueries` over the live modules' sources keyed `['palette-records', source.id, <trimmed query>]` (150 ms after the last key, from 2 characters, `keepPreviousData` between keys, the abort `signal` passed to `search`); a source that fails shows nothing. `todayColumn` takes `{ day, variant, max }` (the post-its as a count, a titled column or grid, or a bare stack); `activities` is a hook or list of hooks returning what the module has running (see "Module activities"); `deviceRows` has the same shape but each component is one `DeviceRow` (`components/device-row.tsx`, a `fieldset` named by the row's label, so tests find it as `group`) in the "Collegati a questo PC" `ServicesPanel` of Dispositivi (`modules/devices/services-panel.tsx`, absent when no live module declares a row; a row may return null while loading); `zone` (`{ id, label, icon, page }`, `page` required) adds a rail entry whose page the module lays out (and gives `ZoneTabs` itself if it needs tabs); `sections` (`{ zone, id, label, component }`) add a tab to any zone page, built-in or another module's, after that page's own tabs (a page that had none then shows the bar); a section aimed at a zone that does not exist is skipped with a `console.warn` at startup (`zones.ts`, `orphanSections`). Section ids are unique per zone. `deck.page` names an existing deck page to add the tiles to, instead of a page of their own (an explicit `at` inserts at that index, as AirPlay does after Pomodoro; without `at` the module's tiles go together to the last page with room, before Sistema's holds: see `shell/AGENTS.md`). Panoramica accepts every widget but places none by default; a default layout applies only until the owner saves it.
- `Tile` has `disabled` for an action that cannot run now (as `pending` does, without the busy state).
- `Tile` without `onPress` is a status tile: a `role="group"` named like the button would be, same look, no press state (used for read-only count tiles). Never pass a no-op `onPress` to keep a tile a button.

- **Module activities.** `ModuleUI.activities` is a hook or a list of hooks (`ModuleActivityHook`, returns `{ id, label, detail, progress?, href }` or null). Chosen so the shell knows whether anything runs without rendering a page: `ActivityBall` mounts one headless `Probe` per hook (so the list may change when a module is switched on or off), the probe calls the hook and reports its result up by id (compared by JSON, so a fresh object each render does not loop). The prop that holds the hook is not named `use`: the React Compiler treats that name as React's `use`, may skip the call and then React sees the hook order change (found as "Cannot read properties of null (reading 'inst')" in the private pass). Lavoro declares two hooks (collection with `searchesDone/Total`, Pareri with `done/(done+remaining)`), each following `onState` through its own client.

## Modules that are off

- The served UI can update before the backend restarts. New catalog response fields need defaults in `settings/catalog-source.tsx`; `catalog.spec.ts` guards the previous API shape.

- Off modules (`lib/enabled-modules.ts`, `useIsOn`/`useLiveModuleUIs` over the protected `modules.enabled`): until it answers everything counts as on. `useZones()` (rail, keys 1-9, palette Vai a; a section-only zone goes when its last section's module is off), `pageTabs` through `useLiveModuleUIs`, `useWidgets()` (the saved layout keeps off widgets, so switching on brings them back) and `useDeckPages()` (`shell/deck-page-config.ts` maps every tile to its module) all filter by it. `modules.enabled` goes over its own `httpLink` (`main.tsx`): in the batch with `health` it broke every spec that pins `health`.

- `ModuleAvailabilityProvider` in `main.tsx` combines `modules.enabled` with each `ModuleUI.useAvailable` hook, using stable per-module layers. `usePending`/`pendingPage` keep zone skeleton geometry. Domain hooks import raw enabled state from `lib/module-enabled.ts`, never `enabled-modules.ts`: the latter imports the UI registry and would create a cycle and leak Vite-only types into module checks.
