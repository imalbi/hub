# Web (`@hub/web`)

## Posta

- `modules/mail/use-mail.ts`: the module's `create` returns an empty router when unconfigured, so `AppRouter['mail']` infers as empty; the client is `createRouterClient<MailRouter>('mail')` (`lib/module-client.ts`, the same transport as `createModuleClient`) typed from `createMailRouter`. Availability is `mail.accounts` (answered from the config, no himalaya call, `staleTime: Infinity`), asked by `useIsOn` on every page: never use `mail.state` for that, it reads every inbox.
- The deck uses only the protected state subscription and displays counts; `list`, `search`, `read` and `threads` are PC-only. A failed account makes the total unavailable; a capped account makes it a lower bound.

React 19 SPA built with Vite. In dev, `/trpc` is proxied to the server (`vite.config.ts`). Two layouts: `/desk` (4K dashboard) and `/deck` (iPhone X PWA, 375x812, no scroll, dark).

## Desk layers and scrolling

- The desk content scroller (`shell/desk.tsx`) is `relative` on purpose: it is the containing block of every absolutely placed node in a page (the `sr-only` live regions of steppers, rows, inspector). Without it they were placed against the body and a long page grew a second, document-level scrollbar (step 33, guarded in `settings.spec.ts`).
- The desk title stays above the content scroller. A tab or module zone with `fill: true` owns its scroll regions: keep controls fixed, pass height through flex children with `min-h-0`, and give each list or reader `min-h-0 flex-1 overflow-y-auto overscroll-contain` with the bottom gutter inside it.

## Where files go

```
src/
  main.tsx, index.css, routeTree.gen.ts
  routes/      file routes only: compose shell and module components, no logic of their own
  shell/       the frame around modules: desk.tsx (DeskShell), rail, zones.ts, zone-page.tsx, zone-sections.ts, widgets.ts, widget-board.tsx (Panoramica), command-palette.tsx, header-slot.tsx, backdrop, header-activity, deck-frame, pages.ts, deck-pages.tsx, use-layout
  theme/       theme.tsx (ThemeProvider), themes.ts, contrast.ts (+ test), theme-panel.tsx (Aspetto picker and editor)
  lib/         trpc.ts, auth.ts, auth-link.ts, use-now.ts, widget-size.ts, zone-search.ts: client plumbing used everywhere
  components/  flat list of shared primitives (panel, tile, registry-button, zone-tabs, page-grid); ui/ = Hairline sources
  modules/<name>/  everything one module shows: desk-panel.tsx, deck-tile.tsx, use-<name>.ts, its provider
```

- A file used by one module lives in that module. It moves to `components/` (UI) or `lib/` (logic) only when a second module uses it. `shell/` never holds module content.
- Flat: at most two folder levels under `src/` (`modules/pomodoro/desk-panel.tsx`); `components/ui/` is the only deeper folder. No folder per component.
- A small piece used by one component stays in that component's file; it gets its own file in the module when a second file needs it or the file passes about 250 lines. No abstraction for later.
- No `index.ts` barrels: import from the defining file. One main export per file, file named after its role in kebab case (`desk-panel.tsx`, `deck-tile.tsx`); hooks are `use-*.ts`. Exported names stay descriptive (`PomodoroPanel`).

## Routing: TanStack Router (file-based)

- Routes are files in `src/routes/` (`__root.tsx`, `index.tsx` redirects to `/desk`, `desk.tsx` (layout), `desk.index.tsx` (Panoramica), `desk.{studio,media,system,devices,settings,lavoro,messaggi}.tsx` (zone pages) and `desk.$module.tsx` (module zones), `deck.tsx`). The Vite plugin regenerates `src/routeTree.gen.ts` in dev and build, `tsr generate` does it before typecheck. It is committed but never edited by hand, and excluded from lint and Prettier.
- Every zone route sets `validateSearch: zoneSearch` (`lib/zone-search.ts`): a zod schema, `z.object({ tab: z.string().optional().catch(undefined) })`, that the router runs as a Standard Schema (`router-core` `validateSearch()` calls `~standard.validate` and fails the whole route on an issue, so a value that is not a string is dropped with `.catch`, never rejected; `?tab=3` arrives as a number). Pages with filters extend it. `/desk/$module` sets `zoneSearch.loose()`: `validateSearch` gets only the query, never the `$module` param, so the generic route cannot pick a module schema and must keep unknown keys; each module validates its own with `zoneSearch.extend` and `.catch` on every field. `zod` is a dependency of the web app at the server's version (one copy in the lockfile); use it for URL state, not for tRPC (those types come from the server).
- In `vite.config.ts` the router plugin must stay before `react()`, or generation and code splitting fail silently.
- Each layout route calls `useLayout('desk' | 'deck')`, which sets `html[data-layout]`; layout-wide CSS (the desk root size) keys off that attribute.

## Data: tRPC + TanStack Query

- `src/lib/trpc.ts` exports `TRPCProvider` and `useTRPC` from `@trpc/tanstack-react-query`.
- Use the options proxy with plain TanStack Query hooks: `useQuery(trpc.health.queryOptions())`, `useMutation(trpc.x.mutationOptions())`. Invalidate with `queryClient.invalidateQueries({ queryKey: trpc.x.queryKey() })`.
- Do not wrap these in custom hooks unless the wrapper adds real logic (combining queries, a shared derived shape). Forwarding options is not logic.
- Types come from the server router. Never redeclare a server type by hand; infer it (`inferRouterOutputs<AppRouter>`) if you need it outside a hook.
- Live state comes from the server's subscriptions: `useSubscription(trpc.x.onState.subscriptionOptions())` (from `@trpc/tanstack-react-query`). `data` is `undefined` until the first push and survives reconnects (only `idle` clears it), which is what lets tiles show the last known state. No `refetchInterval`, and stateful module controls do not invalidate queries: the server pushes the new state. The generic palette dispatcher invalidates cached queries after a successful action because layout and device administration also have query-only state. The `state` queries stay on the server for tests and LLM tools; the web app does not call them.
- Links (`src/main.tsx`): `splitLink` sends subscriptions over `wsLink({ client: wsClient })` and everything else over `httpBatchLink`. `wsClient` lives in `src/lib/trpc.ts`, its URL is built from `location` (so the Vite proxy in dev and the LAN later both work), and the browser sends the page origin with the upgrade: the server refuses any origin not on its allowlist. In dev the page must be on `http://localhost:5173` or `http://127.0.0.1:5173`, or its origin must be in the server config (`server.allowedOrigins`), for example when Vite moves to another port.
- **Auth**: `src/lib/auth.ts` keeps the device token in `localStorage` (`hub.token`, `useToken()` with `useSyncExternalStore`). HTTP sends it as `Authorization: Bearer` (`headers` on `httpBatchLink`), the socket as `connectionParams` (a function, read on every connect). The server decides who a socket is once, when it connects, so `replaceToken(token | null)` in `src/lib/trpc.ts` closes `wsClient` first and the next subscription opens a new one with the new token; use it, never `setToken` alone. `authLink` (`src/lib/auth-link.ts`, first link) turns any `UNAUTHORIZED` answer, from a query, a mutation or a subscription, into `replaceToken(null)`: a revoked or unknown token lands on the pairing screen. A wrong pairing code is `BAD_REQUEST`, on purpose, so it never looks like a lost token.
- `useConnectionLost()` (`src/lib/trpc.ts`, `useSyncExternalStore` over `wsClient.connectionState`) is true when the state is `connecting` with an error, that is the socket closed or failed and the client is retrying; the first attempt has no error and is not "lost". The deck header swaps its status for `connection_lost` and tiles get `stale`. The page recovers by itself when the server comes back, no reload.
- `null` is a real answer (`media.state` with no player); `undefined` data means not loaded yet. Check `=== undefined`, not falsiness.

## Styling: Tailwind v4 + design tokens

Tailwind v4 through `@tailwindcss/vite`, no config file. All tokens live in `src/index.css`, with the reasoning for each scale in comments there. Tailwind's default scales are switched off (`--spacing: initial`, `--text-*: initial`...), so only named steps exist and an off-scale value does not compile.

- **Spacing** (4px base, rem): `3xs 2xs xs sm md lg xl 2xl 3xl 4xl`, chosen by relationship, not by eye: `xs` icon to label, `sm` rows of a list, `md` deck tile padding and related items, `lg` desk panel padding and gap between panels, `xl` between sections, `2xl`+ page margins. Fixed boxes: `touch` (44px minimum target), `icon-sm`, `icon`, `icon-lg`.
- **Type roles**, each with its own line height, tracking and weight: `text-caption`, `text-label`, `text-body`, `text-title`, `text-heading`, `text-display`, `text-hero` (major third scale). Pick a role; never set `leading-*`, `tracking-*` or `font-*` weight by hand to fake a new one. Numbers that change use `tabular-nums`.
- **Radii** `sm md lg xl full`: a shape inside another steps down one level so corners stay concentric (panel `xl`, card inside `lg`, control inside `md`).
- **Colors** only through semantic tokens with shadcn names (`bg-background`, `bg-surface`, `text-muted-foreground`, `border-border`, `bg-primary`, `text-accent`...). Themes are value sets on `[data-theme]`; see "Themes".
- **Desk scaling**: `html[data-layout="desk"]` raises the root font size to 150% for the 3840px viewport at scale 1; everything is in rem, so the whole system scales together. Tune that one number after looking at the real monitor, never individual sizes.
- **No arbitrary values**: `p-[13px]`, `text-[#fff]` and friends are rejected by `pnpm --filter @hub/web lint:tokens` (part of `pnpm lint`). A missing value becomes a new token with a reason, not a one-off. When shadcn/Hairline components land in `src/components/ui/`, exclude that folder from the guard and map their sizes onto these tokens.
- **Private modules and Tailwind.** Source detection covers `apps/web` only, so `index.css` names the private root with an `@source` (a discovery point, see the root `AGENTS.md`); without it a utility used only by a private module's `ui.tsx` generates no CSS and fails silently (`w-touch` squeezed the Lavoro icon buttons to their icon until 16g2). A clone without the folder builds unchanged. <!-- guard-private: allow Repository-local module directory -->
- Font: Urbanist (variable, OFL, self-hosted via `@fontsource-variable/urbanist`), provisional until the font decision in the design doc is closed.
- Third-party notices: `vite build` writes `dist/third-party-licenses.md` (served at `/third-party-licenses.md`) from exactly the packages in the bundle (`build.license` in `vite.config.ts`, with license texts). Vite skips code outside `node_modules` and packages that arrive only through CSS, so `extraNotices` in the same file appends the Urbanist OFL and the vendored Hairline MIT; a new self-hosted font, CSS-only package or vendored source goes in that list. `rough-notation` (0.5.1, exact, MIT, for the Lavoro detail marks) is collected by the build, but it ships `roughjs` inlined, which the bundler does not see: its notice is `third-party/roughjs-LICENSE`, listed in `extraNotices`.
- Components will come from Hairline UI via the shadcn CLI (`npx shadcn@latest add https://hairlineui.com/r/<name>.json`). Generated component code is ours to edit.

## Aesthetic

- Neutrals only, one theme accent for active state and the main figure; other color comes from cover art and photos. Keep the font, Urbanist, and a few weight roles; main figures are large and light.
- Borders are low-opacity 1px hairlines; separators inside panels are dashed. Panels use large radii, nested shapes step down one radius, controls/nav/filters/badges/player are pills. Lots of air and few elements per panel.
- Nav and player float above content and may overlap a panel edge. Only those layers use `.desk-glass`: translucent surface, backdrop blur and hairline in ink; solid surface without blur in paper. Panels stay `bg-surface`. Media backdrop uses blurred/darkened cover art; other zones use a quiet neutral radial gradient; paper uses plain background.
- Charts are greyscale, with the current value solid or in the accent. Do not invent metrics or player features the server cannot provide.
- State changes get short, purposeful motion: selection slides, labels reveal, numbers roll, icons morph. Nothing loops without purpose; the explicitly planned connected badge may breathe, stopping on disconnection/reduced motion. Reduced motion makes transitions instant, including WAAPI icon transitions.
- Every UI step compares its new baselines with the hub references by eye and writes one comparison line per screen in its plan Progress, stating what matches and what deliberately differs.

## Deck tiles

- `src/components/tile.tsx` (`Tile`) is the one deck control: a `<button>` with `aria-label` `"<label>: <state>"` (plus `, <status>` when the optional `status` prop is set: read by screen readers, not shown, for a fact the icon alone carries), an icon (`@phosphor-icons/react`, exported `Icon` type, `size-icon`, `aria-hidden`), a `text-label` label and a `text-caption` state clamped to 2 lines (a tile is ~105px wide at 375px). `pending` disables and dims it; `stale` (the live connection is down) dims it with `opacity-60` and keeps the last state; `error` swaps the state line for `tile_error` in the danger color until the next tap.
- A specific tile owns its state subscription and its mutation and lives in its module folder (`modules/audio/deck-tile.tsx`, `modules/media/deck-tile.tsx`), not in `src/routes/`: every file there becomes a route. `shell/pages.ts` places them on deck pages.
- Loading and unreachable-server copy is generic (`tile_loading` until the first push, `tile_unavailable` when there is no data and the connection is lost); the media tile icon shows the action a tap performs (Pause while playing), and its text is `artist - title` whatever the play state; the play state is the `status` prop (`media_playing`, `media_paused`, `media_stopped`), so the accessible name is `Musica: Artist - Title, in pausa` and e2e locates by role and name. Tile sets stable `data-icon` and `data-weight` hooks on its SVG; media uses `play`/`pause`. Never assert SVG path data.
- Phosphor icons use canonical `*Icon` exports and `regular` by default; `fill` means on/active only in a two-state control. Size through token classes, not numeric `size` props (the library defaults to `1em` SVG attributes). Tile takes `iconName` and `iconWeight`; the Luci bulb keeps one glyph with `regular` off and `fill` on.
- Output labels on the audio tile are values from the user's server config, not Paraglide copy.
- Tapping an action tile against the real server changes the user's audio or playback. Verify taps with the fake server (`pnpm test:e2e`, see `apps/e2e/AGENTS.md`), and take screenshots without tapping. A change to a tile, a layout or a token is covered by `apps/e2e` specs and baselines: the screenshot test fails on any pixel change, so update the baseline only when the change is intended.

- `src/paraglide/` is generated (Vite plugin in dev, `pnpm --filter @hub/web i18n` before typecheck) and gitignored: never edit it.

## No magic values

- Sizes, spacing, radii, colors, durations and font sizes come from theme tokens or the Tailwind scale, never inline literals. If a value is missing, add a token in `src/index.css` and reuse it; a per-file `const SIZE = 24` is a second source of truth that drifts.
- Before building a component, check `src/components/` (and Hairline UI) for one to reuse or extend.

## Conventions

- Function components and named exports.
- Relative imports keep the `.tsx`/`.ts` extension, like the server.
- Touch targets on the deck at least 44px; icon-only buttons carry an accessible label (`aria-label`). Every action button shows pending, done and error states.
- The palette is the Hairline `command-palette` item vendored as `components/ui/command-palette.tsx` (step 20, replacing cmdk; owner, 2026-11-10) and mounted by `shell/command-palette.tsx` (`DeskCommandPalette`, desk only) in the title row of `shell/desk.tsx`: a quiet pill "Cerca... Ctrl K" at the top center (h1 and the right group are `flex-1`, so the pill is centered in the row), accessible name "Cerca o esegui, scorciatoia Ctrl K". A click or Ctrl+K makes the pill itself grow into the palette downwards over the page, Escape folds it back. There is no bottom-right button and no `pb-palette-clear`. The shell builds `CommandItem`s: a **Vai a** group (every rail zone, `onSelect` navigates with the router, never a full load) above **Azioni** (the registry, recent first, Italian labels, the English description as a keyword, the zone label as `meta`). An action with no input runs from `onSelect` (a promise: spinner, check, fold); an action with input, an unsupported schema or `danger` has a `view` page (the chip in the field, Escape or Backspace goes back) that renders `PaletteForm`. Copy is a `copy` prop filled from Paraglide; `emptyText` says loading, the generic error or "Nessun risultato per ..." (a `role="status"` line), and the footer line (`aria-live`) shows pending or the generic failure of a row, never the server message.
- Edits to the vendored file, all deliberate: a native modal `<dialog>` instead of the fixed div (focus trap, inert page, and `Select` portals into the closest `dialog`); every size in rem (the desk root is 150%, the unit is read when it opens, never during render); Phosphor icons and our `Kbd`; `view` pages and `meta`/`note` on items; no `href`; Escape goes back or closes and never clears the query (Escape is handled in capture so a hold cannot swallow it, and in `onCancel` for when focus is on the body, as after a submitted form disables its field); the input is focused as soon as the dialog is shown (a `fill` right after the hotkey must land) and again whenever a page is left, but never when the grow ends while a page is open (Enter before the grow ended opened the page, then the end of the grow stole its focus back: the hold had no focus about half the time, `palette-regressions.spec.ts`); a `session` counter makes a late answer from an old session do nothing, so a slow action cannot close a newer form. Under reduced motion the global desk CSS already kills transitions, so the component's own branch is guarded by a script animation (the page slide), which the e2e check counts.
- The palette mounts over protected `registry.list` (loaded on open); it runs only returned mutation paths through the existing authenticated tRPC client, including private modules, then invalidates every query. `palette-input.ts` admits flat primitive/enum schemas only; nested/opaque schemas stay listed and open a page that says so. `palette-form.tsx` adds `confirmed: true` only after HoldButton confirms, never from a checkbox. Recent storage (`hub.palette.recent`) contains paths only.
- Destructive actions use `components/hold-button.tsx` (`HoldButton`), never a single tap: a wrapper over Hairline `hold-to-confirm` with 800 ms, Italian labels and hint (the vendored component got a `hint` prop for it), an accessible name that says it needs a hold. Its `onConfirm` passes `confirmed: true`, which the server requires for every `danger` mutation (`devices.revoke`, `theme.delete`, `system.suspend/reboot/powerOff`). `outline` gives the quiet pill for a row of several (the power actions); the vendored component got `variant` for it and `min-h-touch` in place of an `h-11` that the token scale does not compile. On the deck the same hold is `components/hold-tile.tsx` (`HoldTile`): tile shape, ring around the icon, built on the vendored `useHoldConfirm`.
- **React Compiler is on** (`vite.config.ts`: `@rolldown/plugin-babel` with `reactCompilerPreset`, Babel 7). No hand-written `useMemo`, `useCallback` or `memo`; if one is truly needed, a comment says why. Vendored Hairline files keep theirs as shipped. `HUB_COMPILER_LOG=1 pnpm --filter @hub/web build` lists components the compiler skips; today `components/ui/use-hold-confirm.ts` and `liquid-tabs.tsx` (suppression comment), `pill-select.tsx` (computed style keys) and `input.tsx` (upstream shapes it cannot lower), plus the private Lavoro `ui.tsx` (a `finally` in `fetchData`). A skipped component runs uncompiled and correctly. Babel must stay on 7: with Babel 8 the compiler 1.0 skips every component that has a default value in its props. Never read the DOM or other outside state during render (computed styles, sizes, `Date.now()`): the compiler memoizes it and it goes stale. Read it with `useSyncExternalStore` (the widget board's grid metrics are the example).
- **Effects only synchronize with something outside React** (the DOM outside the component, timers, sockets, `localStorage`, `matchMedia`). A value computed from props or state is computed during render; a reaction to a user action happens in that event's handler, including updating a parent or a context (call its setter next to your own `setState`, never from an effect that watches your state). oxlint enforces the first two (`react/set-state-in-effect`, `react/no-deriving-state-in-effects`) but cannot see a context or prop setter called from an effect: that case is on review. A cleanup-only effect (reset on unmount) is fine. See react.dev "You Might Not Need an Effect".

## Pomodoro

- `src/modules/pomodoro/use-pomodoro.ts`: one method per action (`timer.start()`, `pause()`, `resume()`, `skip()`, `stop()`) and `timer.act(name)` for the state-driven primary button (`timer.act(timer.primaryAction)`); each returns the request's promise (desk buttons await it, the deck tile catches and shows `timer.error`). It exposes `minutes`/`seconds` numbers (NumberRoll takes them), `time`, `phase`, `paused` and `preset` ("50/10"). The countdown runs on the server's clock: `offset = serverNow - Date.now()` from the latest push, ticks from `useNow(endsAt, offset)`. durationMs keeps progress correct across pauses and late joins. Never complete a phase on the client.
- `lib/use-now.ts` (`useNow(target | 'clock' | null, offset?)`) is the one clock: a `useSyncExternalStore` whose snapshot is the second on screen, with a timeout per caller on the next whole second of the time left (or of the clock); `null` schedules nothing. Never tick with `setInterval` or read `Date.now()` in render.
- `modules/pomodoro/settings.tsx`: the gear in the full panel opens a native `popover` (glass): presets 50/10 (no long break, listed first) and 25/5, custom fields, the sound switch (`.switch` in index.css, a checkbox with `role="switch"`). It saves through `pomodoro.configure`; the server push updates it. The deck tile shows the preset when idle (`Pronto 50/10`), no editor.
- `modules/pomodoro/use-phase-chime.ts` (deck only, `routes/deck.tsx`): plays `chime.wav` (imported from the server module as a Vite asset) with Web Audio when `lastCompletedAt` changes and sound is on. The first tap anywhere unlocks audio (iOS); before that, or on any failure, it stays silent. The PC never chimes from the page: the server plays it.
- `modules/pomodoro/deck-tile.tsx` reuses Tile (Timer icon), tap start/pause/resume only. Compact `Studio` copy keeps phase and remaining time visible in two lines at 375px; skip and stop live only in `modules/pomodoro/desk-panel.tsx`. The panel uses existing tokens, text-display numerals, a native accessible progress element plus a decorative SVG ring, and today's count.
- SVG ring geometry uses pathLength=100 and dash offset from progress. Do not combine pathLength with non-scaling-stroke: Chrome renders a completed arc even at zero. The existing spacing-px token sets the stroke. Tile state text stretches to its content width so long words cannot overflow padding. Both regressions have Playwright checks.

## Desk zones and panels

- `shell/zones.ts` is the rail: Panoramica `/desk`, then the pages Studio `/desk/studio`, Media `/desk/media`, Sistema `/desk/system`, Dispositivi `/desk/devices`, then Lavoro `/desk/lavoro` and Messaggi `/desk/messaggi` only when a module adds a section to them (`work` and `messages` have no content of their own: no rail entry and a not-found page otherwise), then module zones (`/desk/$module`), and Impostazioni `/desk/settings` last. A module zone id is also its path segment: it must not be `lavoro`, `messaggi` or `settings`, which the built-in routes shadow. `routes/desk.tsx` owns the rail/title and Outlet; its `notFoundComponent` says "Pagina non trovata" inside the shell. Named desk-rail and desk-inset spacing tokens reserve a touch target, rail padding/border and content gutters; no arbitrary margin to clear the rail.
- Only Panoramica is a widget board ("Widgets"). Every other zone is a page with no edit mode (no "Modifica"): its route renders `ZonePage zone own` (`shell/zone-page.tsx`), which lists the page's own tabs (`PageTab`: id, label, component) followed by the sections modules aim at it (`shell/zone-sections.ts`, `pageTabs`) and renders them with `ZoneTabs`. A page with one tab shows no tab bar; the first tab is the default. A page with a single tab of its own labels it with the zone name, visible only once a section adds a second. Content is laid out plainly with `PageGrid` and `Panel`s (placeholders until each page's own design; the Media hero and its floating player stay at the top). The full panels (`PomodoroPanel`, `MediaPanel`, `AudioPanel`, `DevicesPanel`, `StatusPanel`, `ThemePanel`) are used as they are, and a widget that has no page panel (`controls`, `power`, Hue `lights`) is placed at its largest size: no second copy of a control.
- `components/zone-tabs.tsx` (`ZoneTabs({ tabs })`, tab = `{ id, label, count?, content }`) is the one tab component (WAI-ARIA tablist/tab/tabpanel, roving tabindex, Left/Right/Home/End, optional rolling count). The active tab is the `?tab=` search param (`/desk/devices?tab=luci`): `activeTab` falls back to the first for a missing or unknown value, `tabParam` leaves the first tab out of the URL, and a click replaces the history entry. Keys `1`-`9` switch zones, never tabs. A module page that needs tabs uses `ZoneTabs` itself; this is the URL-state pattern for filters later.
- `components/panel.tsx` owns the shared surface/border/radius/padding and optional semantic h2/action row, with a unique heading id. Compact Pomodoro/Audio and Status panels (Panoramica) link to their zones.
- Audio outputs: `modules/audio/output-switch.tsx` (`OutputSwitch`) is the configured outputs as one Hairline `ButtonGroup` (the fill glides to the active one, `aria-pressed`), backed by `audio.setOutput({ label })`; it sits in the small widget and in the Media panel. The deck tile still cycles (`cycleOutput`). Media adds volume and mute controls (the volume slider keeps a draft while dragging and writes once on release or key up (`Slider`'s `onValueCommit`), like the Luci slider: one `setVolume` per drag, so parallel `wpctl` calls cannot land out of order), while the small widget places the live volume beside the output to keep its selector inside the fixed cell. The vendored ButtonGroup was adapted: primary fill for the selected pill (the accent had too little contrast), md segments at `h-touch`, and its spacing/radius literals mapped to tokens.
- Keys 1-9 navigate desk zones in rail order. The handler ignores modifiers, repeats, prevented events and input, textarea, select and contenteditable targets; it is removed on unmount. No deck shortcuts were added.
- Paper hover must use a light neutral token such as muted: surface-raised is dark in paper and makes dark secondary text disappear. Active/inactive rail hover classes are separate for the same reason.
- Full Pomodoro draws its entire border-token track under the progress arc; compact overview omits ring/daily statistics/skip-stop. Preserve the normalized SVG fix described above.

## Themes

- Built-in themes are CSS in `index.css`: `ink` (Scuro, also the `:root` default), `paper` (Chiaro), `moss` (Muschio) and `stone` (Pietra), the last two chosen with the taste skills. Each sets every color token plus `--glass`, `--glass-border`, `--glass-filter`, `--backdrop-glow` and `--backdrop-art-display`: dark themes frost the floating chrome and show the blurred cover, light ones turn both off. Never key a rule on a theme name (`[data-theme='paper'] .x`); add a variable instead. Each also sets `color-scheme` (dark or light), and `themeCss` does it from `mode`: without it the browser drew native controls for a light page, so the date picker icon was dark on dark (`themes.spec.ts` checks it per built-in theme).
- Themes held as data (Caelestia from the server, the owner's custom ones, the editor's `draft`) are drawn by `ThemeProvider` into one `<style>` through `themeCss(id, values)` (`theme/themes.ts`). Only `#rrggbb`/`#rrggbbaa` values reach it: the server validates with zod, `themeCss` checks again and drops a theme with any other value. Ids are `caelestia`, `custom-<id>` and `draft`.
- `ThemeProvider` (`theme/theme.tsx`) wraps both the desk shell and `/deck` (`remote` false on an unpaired deck: built-in themes only). The choice is per device in `localStorage` `hub.theme`; `setPreview(id)` shows a theme without choosing it (hover on a card); a theme that cannot be drawn resolves to a fixed one (deleted custom: `ink`; Caelestia missing or with unreadable text: `ink`/`paper` by its mode).
- Contrast (`theme/contrast.ts`, unit tests via `pnpm --filter @hub/web test`): 4.5:1 for foreground on background and surface, muted text on surface, button text on button; 3:1 for the accent on surface (focus ring). Borders are decorative hairlines and are not checked. The editor blocks saving below these, the Caelestia theme falls back when foreground on background fails.
- Theme changes glide: the color variables are registered with `@property` (`<color>`, end of `index.css`) and `html` transitions them over `--motion-standard`, so the browser interpolates every color and a change in mid-glide starts from the current one. The View Transitions API was tried first and dropped: it applies the theme asynchronously and skips a running fade when a new one starts, which flashed the wrong theme while moving between cards. A new color variable used by themes must be registered there too. Hover previews start after the pointer rests 200 ms on a card.
- The theme editor opens in a modal side sheet (`<dialog>`, `--spacing-sheet`, transparent backdrop) so the widget never grows and most of the page stays visible as the live preview; Esc cancels.
- Aspetto (`theme/theme-panel.tsx`, the page `/desk/settings/appearance` of Impostazioni; also a Panoramica widget): a radio group of cards, each a miniature desk scoped with `data-theme`; duplicate any theme (a built-in one is read from its rendered preview through a 1px canvas, which converts oklch to hex), edit with live preview of the whole page, delete with hold-to-confirm. e2e chooses a theme by clicking its name (`apps/e2e/tests/themes.ts`).

## Widgets (Panoramica)

- Panoramica is the only phone-style board (`routes/desk.index.tsx` renders `WidgetBoard`; the default layout is `defaultLayout` in `shell/widgets.ts`) and it offers every widget, built-in and from modules, including those that also appear on a page. The header's Modifica/Ripristina/Fine uses it. CSS `.split-pill` in index.css; the extra button stays mounted and `inert` so it can animate out.
- Edit mode ("Modifica" in the header, through `HeaderActions` and the shell's header slot): items drag (whole cell, `.widget-tools` excluded), the content is `inert`, a size pill (P/M/G/L, full names as radio labels) sits bottom left and move-before/after (the keyboard path; the library has no keyboard drag) plus remove top right; "Aggiungi widget" lists missing ones; "Ripristina" resets. Layout animations run only in edit mode (no widgets growing in on load) and never with reduced motion.
- Saved on the server (`layout.get/save/reset`, `desk_layouts`, the `overview` row only: the server refuses any other zone); the client updates the query cache and saves, and drops ids or sizes it does not know. e2e waits for `layout.save` before a reload and for the grid's animations before measuring (`apps/e2e/tests/widgets.spec.ts`).
