# Theme (web)

- Built-in themes are CSS in `index.css`: `ink` (Scuro, also the `:root` default), `paper` (Chiaro), `moss` (Muschio), `stone` (Pietra) and, since step 53, `night` (Notte), `ember` (Brace), `lagoon` (Laguna). The last three are hex values frozen from `deriveColors('dark', seed)` at contrast 70 with the seeds in `builtInSeeds` (`theme/derive.ts`); `derive.test.ts` fails if the CSS and the seed drift apart. A new built-in theme is: a CSS block, a row in `builtInThemes`, a seed in `builtInSeeds`, name and note in `modules/theme/messages/it.json`, the note in `builtInNotes` (`theme-panel.tsx`). Each sets every color token plus `--glass`, `--glass-border`, `--glass-filter`, `--backdrop-glow` and `--backdrop-art-display`. Glass is on every theme: dark ones glass at 72% of `--surface` with the cover shown at 0.1, light ones at 70% with the cover at 0.04 and `--backdrop-glow: color-mix(in oklab, var(--accent) 12%, var(--background))` (a tint strong enough to blur, weak enough that muted text on the glass stays at 4.5:1; a stronger mix breaks that, e2e `glassRatios`). Never key a rule on a theme name (`[data-theme='paper'] .x`); add a variable instead. Each also sets `color-scheme` (dark or light), and `themeCss` does it from `mode`: without it the browser drew native controls for a light page, so the date picker icon was dark on dark (`themes.spec.ts` checks it per built-in theme).
- Themes held as data (Caelestia from the server, the owner's custom ones, the editor's `draft`) are drawn by `ThemeProvider` into one `<style>` through `themeCss(id, values)` (`theme/themes.ts`). Only `#rrggbb`/`#rrggbbaa` values reach it: the server validates with zod, `themeCss` checks again and drops a theme with any other value. Ids are `caelestia`, `custom-<id>` and `draft`.
- `ThemeProvider` (`theme/theme.tsx`) wraps both the desk shell and `/deck` (`remote` false on an unpaired deck: built-in themes only). The choice is per device in `localStorage` `hub.theme`; `setPreview(id)` shows a theme without choosing it (hover on a card); a theme that cannot be drawn resolves to a fixed one (deleted custom: `ink`; Caelestia missing or with unreadable text: `ink`/`paper` by its mode).
- Contrast (`theme/contrast.ts`, unit tests via `pnpm --filter @hub/web test`): 4.5:1 for foreground on background and surface, muted text on surface, button text on button; 3:1 for the accent on surface (focus ring). Borders are decorative hairlines and are not checked. The editor blocks saving below these, the Caelestia theme falls back when foreground on background fails.
- Theme changes glide: the color variables are registered with `@property` (`<color>`, end of `index.css`) and `html` transitions them over `--motion-standard`, so the browser interpolates every color and a change in mid-glide starts from the current one. The View Transitions API was tried first and dropped: it applies the theme asynchronously and skips a running fade when a new one starts, which flashed the wrong theme while moving between cards. A new color variable used by themes must be registered there too. Hover previews start after the pointer rests 200 ms on a card.
- The theme editor opens in a modal side sheet (`<dialog>`, `--spacing-sheet`, transparent backdrop) so the widget never grows and most of the page stays visible as the live preview; Esc cancels.
- Aspetto (`theme/theme-panel.tsx`, the page `/desk/settings/appearance` of Impostazioni; also a Panoramica widget): a radio group of cards, each a miniature desk scoped with `data-theme`; duplicate any theme (a built-in one is read from its rendered preview through a 1px canvas, which converts oklch to hex), edit with live preview of the whole page, delete with hold-to-confirm. e2e chooses a theme by clicking its name (`apps/e2e/tests/themes.ts`).
- Custom themes are a seed (`theme/derive.ts`, OKLCH) plus roles set by hand (`manual`); the server stores `colors`, `seed` and `manual` in the `themes.values` JSON. A theme with no `seed` is legacy and opens with every role manual. Keep `deriveColors` passing `derive.test.ts` (every preset pair and hue at contrast 70 passes `contrastFailures`).
- Per-device settings (`hub.radius`, `hub.glass`, `hub.backdrop`) are mirrored on `<html>` as `data-radius`, `data-glass`, `data-backdrop` by `useDeviceSetting` in `theme/theme.tsx`; the effects are CSS in `index.css`. Radii only scale `--radius-lg` and `--radius-xl`. Floating chrome uses the `desk-glass` class so Vetro off reaches it; the cover backdrop opacity is the per-theme `--backdrop-art-opacity` (0.04 on light themes: their secondary text has no room for more).
- A theme swatch strip draws with a nested `data-theme` element; no color is read back from computed style.
