# System (server)

- `modules/system/router.ts`: `lock` (`caelestia shell lock lock`: Caelestia's lock screen, the one Super+L opens; `loginctl lock-session` was planned but a user service has no login session to name), `suspend`, `reboot`, `powerOff` (`systemctl suspend|reboot|poweroff`, `danger`, input `confirmed: z.literal(true)`), `toggleWorkspace({ name: 'communication' | 'music' | 'hub' })` (`caelestia toggle <name>`, the special workspaces of Super+D, Super+M, and Super+H). A non-zero exit is `INTERNAL_SERVER_ERROR`. The service gets `HYPRLAND_INSTANCE_SIGNATURE` from the user manager, which `caelestia` needs.
- Monitors (step 34): config `system.monitors: [{ output, label, command }]` (empty by default, edited as a table in Impostazioni). `system.monitor.toggle({ output })` runs that entry's `command` with no argv through `ctx.run` (Hub never builds `hyprctl eval`: re-enabling needs the monitor geometry, which stays in the owner's script); the input is a zod enum of the configured outputs, and with an empty list the enum cannot exist, so it takes a string and answers 412. `system.monitors` / `onMonitors` read one `hyprctl monitors all -j` for every entry (`monitor.ts`, `name`, `disabled` and optional integer `transform` parsed): `on`, `off`, `absent` (not listed), `unknown` (failed or garbled). The live hub polls every 5 s while subscribed and `toggle` calls `notify()`; this is the plan's fallback for decision 2. Installed Hyprland has `monitoradded`/`monitorremoved` event names (strings in the binary) but whether a disable emits one, and whether the service has `HYPRLAND_INSTANCE_SIGNATURE`, could not be checked without touching the real desktop; the event socket is in BACKLOG. The registry lists the toggle even with no monitor configured (a router cannot be conditional without breaking the inferred types), so the palette shows a failing action then. The fake desktop answers `hyprctl monitors all -j` from `modules/system/fixtures/monitors.json` plus its `monitors` option (`fakeMonitors()`, disabled flag per output), and a script named `fake-monitor-<output>` flips it; e2e hook `POST /__fake/monitor { output, disabled }` plays the owner's shortcut.
- Never run the power actions on the real machine, not even to check them: the fake desktop records lock, power and toggle argv in its `system` array (exact argv only; `systemctl halt` and the rest are refused).
- Consumption (`modules/system/power.ts`, `system.power/onPower`, polled every 5 s while subscribed): config `system.powerstatDir` (unset: null, the UI says it is not configured). The owner's tracker writes `status.json` (`ts` epoch seconds, `total_w`, rewritten every ~2 s) and `samples.csv` (`iso` local time without offset, `total_w`, one row a minute). Watts now come from the status, null when older than 30 s; today's kWh integrates the samples since local midnight, each row standing for the time since the previous one, gaps over two minutes skipped. Checked on the real data: within 0.3% of the tracker's own session totals. `samples.csv` passes a megabyte, so it is parsed again only when its mtime changes. Fixtures in `modules/system/fixtures/powerstat/` are invented values; `fake.ts` writes a dir with a status dated 2100 (never stale) and an hour at 150 W today.

- Monitor orientation (step 107): optional `horizontalCommand` / `verticalCommand` are manual binaries, invoked with no argv by `monitor.setOrientation`. `parseMonitors` returns null orientation unless enabled with a known transform (odd vertical, even horizontal); `readMonitors` adds only capability booleans, never command paths. Successful orientation commands notify the live hub. The fake supports `fake-horizontal-<output>` / `fake-vertical-<output>` and `/__fake/monitor` accepts an optional transform.
