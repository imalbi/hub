# Media (server)

- playerctl: `--format` does not expand `\t`, so `MEDIA_FORMAT` carries real tabs. "No players found" exits non-zero and is `null` state, not an error.
- Media metadata adds art URL and MPRIS length after the title; parse the trailing fields so title tabs survive. `parseMediaMetadata` is server-only; `parseMediaState` returns nullable lengthMs (microseconds converted to milliseconds) and a 16-character SHA-256 artKey, never the URL. `next`/`previous` use exact playerctl argv through injected run and notify the same hub; errors never forward raw player stderr to clients.
- `modules/media/live.ts` reads position through the selected player's `playerctl position`; seek uses the same preference and validated seconds. When preferred mpv lacks artwork, its `xesam:url` must be a validated YouTube Music watch URL before constructing the server-only thumbnail URL; state and `media.art` share this selection and never expose either URL.
- `modules/media/art.ts` owns one last-cover cache per server, created in the media module's factory. Protected media.art takes no source input, re-reads the current player metadata and accepts only its file: or https: URL. HTTPS uses a 3 s abort signal and refuses redirects; declared and streamed bodies and file reads are capped at 2 MiB. MIME comes from PNG/JPEG/WebP signatures, never an extension/header. Missing, oversized, invalid or unavailable art returns null; errors never expose its source. Tests pass `deps.fetch` to buildServer and never fetch real artwork. No artwork enters SQLite or tracked files.
- Local artwork opens with O_NONBLOCK before descriptor validation; a FIFO with no writer must never occupy a filesystem worker indefinitely. art.test.ts creates only a disposable temporary FIFO and probes it in a child with a hard deadline, alongside regular image/non-image/oversize fixtures.
- Fake media has three generic tracks, a generated geometric fixture (modules/media/fixtures/cover.png, recreated by generate-cover.ts), and next/previous preserve play status. E2E restoration returns both the track and status to their defaults. Real next/previous are never an automated check; smoke only reads metadata/help.
