# News (server)

- `modules/news/`: `page.ts` (`parseDigestPage`, `createNewsLive`) and `router.ts` (`news.state/onState`, `refresh`, `open`). Config `news.page` (the HTML the owner's webdigest writes; unset hides news), `news.stateFile` (its JSON state; only its mtime is read, as "last run"), `news.command` (the script).
- The count comes from the page, not the state file: the header nav has one link per section with its item count in a span (the state file only lists seen links). `fresh` is false when the state file is more than 10 s newer than the page, that is the last run found nothing and left the old page. The page is parsed again only when its mtime changes. The fixture keeps the script's one-line header; `.prettierignore` skips `modules/news/fixtures/` so Prettier never reflows it.
- `refresh` runs `<command> --no-open` with a 60 s timeout (`-1` from `run` is `TIMEOUT`, 408): `--no-open` regenerates without a browser window. A real run marks the new items as seen for the owner, so it never runs in tests or checks; the fake desktop records `webdigest --no-open` and `xdg-open <page.html>`. `open` is `xdg-open <page>` on the PC.
- The script has no `--help`: an unknown flag is ignored and the digest runs for real (it happened once while planning this module). Only `--test` (its self-check, exactly that argv) is safe; `pnpm smoke` uses it and parses the configured page.
