# E2E (`@hub/e2e`)

Playwright (Chromium only) against a fake server: the real server code with a fake desktop, so nothing touches the real audio, players or config. Run with `pnpm test:e2e` from the root (part of `pnpm verify`); it has no `test` script on purpose, so `pnpm test` and `pnpm check` stay fast.

## How it runs

- `playwright.config.ts` starts two `webServer`s and stops them itself: the fake server (`apps/server/src/testing/fake.ts`) and Vite (`--strictPort`, proxying `/trpc` to the fake server through `HUB_PORT`). **Every run picks two free ports and a temp folder of its own** in `tests/hosts.ts` (a child process binds two port-0 sockets, reads them, closes them; the result goes into `HUB_E2E_SERVER_PORT`, `HUB_E2E_WEB_PORT`, `HUB_E2E_TMP` for the workers and the servers, and the folder is removed on exit). Import `SERVER_URL`, `PC_URL`, `PHONE_URL`, `RUN_TMP`, `DECK_STATE` from there; never write a port or a `/tmp/hub-e2e-*` path in a spec. `reuseExistingServer: false`: a busy port is an error, never a run against `pnpm dev`.
- The fake server allows the origins of this run's Vite (`HUB_E2E_WEB_PORT`) in its fixture config; without them every WebSocket upgrade is refused with 403 and the deck shows "Connessione persa". Its fixtures (Caelestia scheme, news page, powerstat) are written under `HUB_E2E_TMP`, which `themes.ts` reaches through `RUN_TMP`.
- **Vite keeps one dependency cache per config variant** (`HUB_VITE_CACHE`, `apps/web/node_modules/.vite-e2e/<hash of module root and example flag>`, set only for e2e). Two Vites whose config differs (the example pass and a private pass, which run together in `pnpm test:e2e`) that share `node_modules/.vite` both log "Re-optimizing dependencies because vite config has changed" and the page under test reloads: the example pairing setup then times out after 30 s. `pnpm dev` and `pnpm serve` do not set the variable and keep the default cache.
- Projects: `setup` runs `pair.setup.ts` first; `deck` (375x812, scale 3, the paired state) runs `deck.spec.ts`, `pairing.spec.ts` and `deck.visual.spec.ts`; `desk` (1920x1080) runs the desk functional and visual specs. `playwright.config.ts` explicitly lists each project's specs: register every new file there or it will not run.
- **Pairing for real, once per run**: `pair.setup.ts` opens /desk/devices, clicks Genera codice, reads the code, opens a fresh browser context on the deck, types it on the pairing screen, waits for the tiles and saves the state (token in `localStorage`) to `DECK_STATE` (`deck.json` in the run's temp folder: it belongs to that run's fake server, which starts empty, so two runs must not share it). The `deck` project reuses it through `storageState`; `pairing.spec.ts` and the unpaired visual test start empty with `test.use({ storageState: { cookies: [], origins: [] } })`.
- **PC and phone are two host names for the same machine**: `tests/hosts.ts` has `PC_URL` (`localhost`, project `desk`) and `PHONE_URL` (`127.0.0.1`, project `deck`), both on the run's Vite port. The Vite proxy keeps `Host`, and the fake server (`testing/fake.ts`) trusts only `localhost` as the PC. The `pc` and `phone` fixtures (`tests/fixtures.ts`) are the same two clients over plain HTTP. Keep new specs on the right host or they will meet a 401.
- First run on a machine or after a Playwright update: `pnpm --filter @hub/e2e exec playwright install chromium`.
- `pnpm test:e2e` runs the public pass and, next to the private pass, a second pass with `HUB_EXAMPLE_MODULES=1` in the test process only: `playwright.config.ts` then points `HUB_MODULES_ROOT` of the fake server and Vite at `modules.example/` and runs only `modules.spec.ts` and the specs listed for it, so the example travels the private-module path (server discovery plus the `@hub-private-modules` glob). The public pass uses an empty root and checks the example is absent.
- Ports are free ones picked per run, so a manual fake/Vite server can never block a run and a run never needs 4190/5190. Use the registered 4K specs for inspection, and stop servers you started by PID.
- **The fake restarts in place** (`apps/server/src/testing/fake.ts`): `settings.onRestart` closes the server, waits `HUB_E2E_RESTART_MS` (1500 by default) and builds it again from the fixture config plus `hub-e2e-config.json` in `RUN_TMP`; the core database is a file there too, so paired devices and module data survive. Top-level keys of that file replace the fixture's, so a spec must not save a public module's _slice_ (it would drop the fixture's paths or short durations): switch a module, or save a slice nothing else reads. Waiting for the page to come back needs a long timeout (the socket reconnects with a back-off); the Vite proxy logs ECONNREFUSED meanwhile, which is expected. A page that must survive a restart without reloading sets a `window` marker and checks it after.

## Writing specs

- `mcp.spec.ts`, the deck confirmation test and the Agent test in `devices.spec.ts` use the fake server and `/__fake/system`; never run a real desktop action.
- Locate by role and accessible name (`getByRole('button', { name: /^Uscita audio/ })`, `toHaveAccessibleName`): it checks the names AGENTS.md requires. The icon of a tile is the exception, assert its intentional `svg[data-icon="play"]` / `svg[data-icon="pause"]` hook. Phosphor icons use `regular` by default; the Luci bulb uses `data-icon="lightbulb"` with `data-weight="fill"` when on and `regular` when off. Never match SVG path data.
- Wait with auto-waiting assertions, not sleeps. The connection-lost state needs a longer `timeout` (the tRPC client backs off between retries).
- A revoked or unknown token ends on the pairing screen (see `pairing.spec.ts`), not on "Connessione persa"; that state is for a dropped socket.
- Dropping the API WebSocket: use `controlSockets(page)` (`tests/sockets.ts`, call before `goto`). `page.routeWebSocket` with an instant `ws.close()` does not work: the socket opens first and the tRPC `wsClient` then skips its retry and stays dead. `context.setOffline` leaves open sockets alone. The helper must only track/refuse /trpc sockets: closing Vite's HMR socket triggers a full reload and makes the outage test race with navigation. deck.spec.ts asserts the HMR socket remains open.
- `pomodoro.spec.ts`: afterEach stops any active phase; completed history is intentionally retained.
- Headless Chromium downloads the PDF blob instead of showing its viewer, so the spec checks the blob URL, page fragment and inline response; visual Studio and Libreria baselines cover both themes at 1920 and 4K.
- `pomodoro.spec.ts` records every frame's readable time and whether a digit is rolling (`recordTimerFrames`): the first real value must not roll in from 00:00 (paused frozen state, 20 frames after it shows), and a later tick still rolls (real fake-server phase). The roll on load had made the paused baseline bistable once the page rendered before the state arrived; capture with reduced motion only to hide something that is meant to move.
- The idle-ring regression counts bright foreground pixels in a screenshot of the SVG (must be zero). The paused tile's text must stay inside its padding. These checks guard real rendered behavior, not just SVG attributes or source strings.
- Pair setup and devices.spec.ts open /desk/devices; pomodoro.spec.ts exercises the full panel at /desk/studio. Overview has only compact controls. Keep assertions on their real zone rather than restoring old overview content for a test.
- zones.spec.ts covers exact active links, all six rail destinations (Impostazioni last) and direct Studio load, number shortcuts/editable input/modifiers (the focused-button case uses the palette pill: a radio is an input and the handler skips it), saved theme/reload, SPA exit to deck/back (ink then restored paper), the fresh deck retaining its computed ink background, and real fake-server playback/output cycling (restored in finally). A paper hover test computes WCAG contrast for Salta/Ferma; the original ratio was 1:1.
- The deck has its own `ThemeProvider`, defaulting to ink and restoring `hub.theme` from that browser's storage (step 08). Assert the rendered background when checking theme isolation, not the absence of a data-theme attribute.
- contrast.ts measures rendered colors in a canvas; both rail-label and Pomodoro hover regressions require 4.5:1.
- Artwork recovery tests return null or another key once, then the valid fake cover; both must recover with one retry. A frozen Pomodoro plus page.clock verifies that visible time changes while a MutationObserver sees no updates to the phase-only polite announcement. These regressions guard against infinite freshness of failures and a screen reader announcing every second.
- `system.spec.ts` (desk) and the Sistema test in `deck.spec.ts`: consumption from the fake powerstat dir (212 W, 0,15 kWh oggi), lock and workspace buttons reach success, power off fires only after the hold. The argv of each command is a server test, the fake never runs them.
- The fake config copies `modules/news/fixtures/latest.html` (22 items) to the temp dir with a fixed mtime (4 Nov 08:30), which is the "Aggiornato" line in the baselines.
- `zone-pages.spec.ts` runs in both passes: every page has no "Modifica", no `Widget` region and no `[data-widget]` (each waits for a landmark of its page first, so "nothing here" cannot pass on an empty screen); Impostazioni shows Aspetto and a chosen theme applies; the last row of a page is fully visible with the same gutter below as above (a 500px-high viewport on Media, scrolled to the end: no clearance for a floating layer, step 20). First pass: one tab, no bar, `?tab=hello` changes nothing.
- `modules.spec.ts`: example pass has the example zone as a page, the example widget offered in Panoramica (adding and resizing each save the board, so wait for each save, not one) and Lavoro in the rail with the example section as its only tab; first pass has no Lavoro or Messaggi entry and `/desk/lavoro`, `/desk/messaggi` say "Pagina non trovata".
- The tabpanel is the body inside the surface frame (`[data-page-surface]`): measure the right gutter and bottom gap on the frame, scroll the tabpanel. `widgets.spec.ts` checks Panoramica's surface and at least 16px between Modifica and the first widget; the drag test scrolls the audio widget into view first (it starts below the fold).
- Musica (step 48): `music.spec.ts` covers every flow of the page; recent tiles come from history, which the fake cannot seed (30 s of playback), so that spec fulfils `music.history` through `answerQueries` (it intercepts every `/trpc/*` URL: a glob on the first procedure missed batches led by another one, and the devices 5/7 test flaked under load).
- The surface-bottom-gap check exempts Media (`float`: `mb-3xl`).
- Desk surfaces have no status line (step 91); measure columns against the surface. Panoramica's widget cells keep a hairline (board I1), so `zone-pages.spec.ts` checks borders only on panels outside `[data-widget]`.
- Stubs that answer `agents.localCalls` must also answer `agents.localCallsToday` (0), or the Su questo PC line depends on calls other specs made.
- The core settings sticky check scrolls the surface's section (`[data-page-surface] section.overflow-y-auto`, inside the surface body), not the desk scroller.
- Private Lavoro specs: the tab bar is inside the surface since 47c (it was above it in 47b, `ownTabs`).
- `music.spec.ts` shares one music queue per process: radio skips songs earlier tests played, so assert the first upcoming row, not a fixed title. The thin seek bar keeps an `aria-hidden` value bubble with the same text as the elapsed time: take `.first()` for the inline time.
- `themes.spec.ts` `glassRatios` computes text on the glass over the worst ground (the glow, a black cover at the backdrop opacity, the glass alpha), reading colors through a canvas so `color-mix` values work.
- The desk project launches Chromium with `--use-fake-device-for-media-stream --use-fake-ui-for-media-stream`; the webcam spec reads `srcObject` tracks through an element handle and checks `readyState` is `ended` after close and after a route change (poll: unmount is not synchronous with the heading). The denied and missing cases override `getUserMedia` in an init script.

- `pomodoro-visual.ts` forwards the real fake-server WebSocket and replaces only Pomodoro state for screenshots, so history and wall time cannot leak between specs. Idle and half-completed paused fixtures are explicit; functional specs never pin the subscription.
- Desk is checked at 1920x1080 and 3840x2160; deck at 375x812.
- Every desk baseline shows the rail with the palette magnifier and status dot, no title row (step 47 slice 1) and, since 47c, the activity ball at the top left by default (and draggable): the fake player is always playing or paused, so the music ball is in every desk baseline (`/__fake/player` with `{ gone: true }` removes it; `restoreDesktop` restores it). The h1 is `sr-only`: `getByRole('heading', { level: 1 })` still finds it, `zones.spec.ts` checks one per page and its 1px box. The connection status is `getByRole('status', { name: 'Connesso' })` inside the rail navigation. The per-zone snapshots use pinned health/device data and frozen Pomodoro subscription state; deck baselines are unchanged.
- The deck baseline files are unchanged by 07b; do not update them for desk work. Only desk images are regenerated during this pass. A global CSS or shared-hook change must still pass the existing deck screenshots in verify.

The timer's text is its direct `:scope > .sr-only` child (NumberRoll has its own sr-only nodes). `pomodoro.configure` changes the fake server for later tests: a test that calls it restores the fixture durations in `finally`.

- `jobs.spec.ts` and the jobs case in `deck.spec.ts` start the fake timer-driven command through `/__fake/jobs`, never a real desktop process. The log baseline hides variable timestamps, counts and rows after the first three.
- Baselines changed by the layout: `agent-section`, `desk-code`, `desk-devices`, `desk-devices-4k`, `desk-devices-tabs`.
- The light glass differs from the solid surface by a few percent of luminance, so `desk-paper`, `desk-media-paper` and `desk-stone` passed under the 0.2 threshold with the old baselines; they were rewritten with `--update-snapshots all -g "in paper|in Pietra"` and the pixels checked. `--update-snapshots changed` alone would have left them stale.

## Parallel run

- `pnpm test:e2e` is `scripts/test-e2e.ts`: it takes the lock `hub-e2e-lock` in the git dir (pid inside; a second run says "waiting" once and waits, a dead pid is taken over), builds one production bundle per variant in parallel (`vite build` into `apps/web/node_modules/.e2e-dist/<variant>`: the module root and `HUB_EXAMPLE_MODULES` are baked at build time, so public, example and each private module need their own; the build pins the example flag to 0 like the dev config did, or every example module registers twice), then runs a queue with `WORKERS` slots (3, owner cap 4) and no stage barrier: a slot takes the next job as it frees. A failing job stops new jobs, running ones finish, exit 1. Jobs print as `[label] line`; the run ends with `EXIT <code>` (written by `scripts/verify.ts` instead when run inside verify).
- Playwright serves the build with `vite preview` when `HUB_E2E_DIST` is set (same `/trpc` proxy as dev); without it, a dev server. Measured 2026-11-13: a 22-test slice took 58 s on dev and 20 s on preview. Two things stay on a **dev server** (their own job per variant, `public-dev` and `example-dev`, `devServerSpecs` in the runner; the example pass ran `pomodoro.spec.ts` on its build until step 88 and the remount case failed there 2 runs of 4: the screen-reader text of the remounted Panoramica timer reads 00:00 while the digits are right, open in `plans/BACKLOG.md`): `palette.visual.spec.ts` (zero-tolerance baselines; the 4K palette opens 1 px higher on a build) and `pomodoro.spec.ts` (the digits of a remounted timer stayed at 00:00 in about 1 run of 4 on a build, never on dev). Private passes also stay on dev: their specs are time-bound, the build did not shorten them (3.7 min against 3.0) and 9 of 42 failed on it. `deck.spec.ts` connection-lost checks that any non-tRPC socket (Vite's HMR one, only on dev) stays open, instead of waiting for one.
- Shards are not `--shard`: the runner lists each variant's spec files (`--list --reporter=json`), weighs them by last run's seconds (`hub-e2e-durations.json` in the git dir, written after every run; 2 s a test for an unknown file) and fills bins longest-first, passing file paths to Playwright. Public shards ended within 5% of each other (84, 86, 88 s).
- The parallelism is processes, not Playwright workers: each process has its own fake desktop, two free ports, a temp folder and its own pairing (`pair.setup.ts` runs once per process, so every job shows one setup test more). A worker-scoped fixture would have meant rewriting every spec that reads the host constants. One test per process at a time is still the next lever (see `plans/BACKLOG.md`).
- Specs never see each other's state across processes. They still must not depend on the order of files inside a process, and timing-sensitive specs (Pomodoro, the palette) can fail when the machine is saturated: a fourth process made `pomodoro.spec.ts` and `study.spec.ts` "a large plan" fail, three did not.
- `Unable to transform response from server` in the private run's log is expected: `optimistic rollback on forced mutation failure` fulfils a 500 with a body tRPC cannot parse on purpose. It is not a sign of a failing run (it also appears in a green serial run).
- `pnpm test:e2e:update` stays serial on a dev server: baselines are rewritten from one process.
- The first failure artifacts live in `test-results/`, which every Playwright process empties at its start: two runs started at once keep only what the later start leaves.
- Waiting: run `pnpm test:e2e` or `pnpm verify` and wait for the command (or its completion notification); the `EXIT <code>` line is there for logs. Never poll a log in a loop.

## Fake hooks

- `activity.spec.ts`: `/__fake/player` sets `{ gone: true }`; `restoreDesktop` posts `{ gone: false }`.
- `jobs.spec.ts`: `/__fake/jobs` starts a fake job; cancel it after the test. `{ clear: true }` empties the finished history, which is per process: a spec that asserts the empty list clears it first.
- `system.spec.ts`: GET `/__fake/system` reads recorded fake system calls; it does not change state.
- `system.spec.ts`: `/__fake/monitor` sets the fake output state; restore it in `finally`.
- `mail.spec.ts`: `/__fake/mail` sets `{ fail: true }`; reset with `{ fail: false }` in `finally`.
- Fake hooks (`/__fake/*`) exist only on the fake server: post to `${SERVER_URL}/__fake/...` (an absolute URL, also through the `pc` fixture), never a relative path on `pc`. `restoreDesktop` had that bug and left the player gone after any test that removed it.

## Traps when locating and waiting

- `desk.visual.spec.ts`: Baselines are committed in `__screenshots__/<project>/<name>.png` (CSS pixel size, no platform suffix: they are made on the owner's Linux machine). No pixel may differ beyond Playwright's default per-pixel colour `threshold` (0.2, not zero): a small colour change (a dark grey badge going a shade darker) passes, and `--update-snapshots=changed` then leaves the old PNG. After an intended subtle change, update the affected files with `--update-snapshots=all` and check the pixels.
- `pomodoro.spec.ts`: before the first push the timer's hidden text is the `00:00` placeholder, so a wait for `/^\d\d:\d\d$/` after a remount passes on it; wait for a value that is not `00:00` (the remount test failed 1 run in 4 after 81cfea8 on that race; it may be the "digits stayed at 00:00" seen on a build).
- `pomodoro.spec.ts`: NumberRoll adds decorative digit strips to the desk timer. Read the timer's direct `:scope > .sr-only` child for the exact time (step 08 removed the hidden output and the description). Never compare the entire decorative DOM text. Deck text assertions stay unchanged.
- `desk.visual.spec.ts`: Move the pointer away before normal screenshots so the focused/hovered rail label cannot leak into a page baseline; hover readability has its own functional test. Continue freezing uptime, devices, pairing code, clock and Pomodoro; disable animations and await artwork when present.
- `deck.spec.ts`: The deck has two built-in pages; a test that switches page clears `hub.deck.page` (and `hub.theme`) in `finally`. A swipe is `.deck-pages` `scrollTo`. Tiles on pages off screen are hidden from role queries, so `getByRole('button', { name: /^Pomodoro:/ })` still finds one.
- `deck.visual.spec.ts`: Holding: hover, `page.mouse.down()`, advance `page.clock`, `mouse.up()`. The mid-hold baseline pauses timers (`clock.pauseAt`) and pins every WAAPI animation at 400 ms. Danger mutations from test helpers pass `confirmed: true`.
- `modules.spec.ts`: Baselines `desk/desk-example-4k.png` and `desk/deck-example.png`; the deck one pins `health` like the other visual specs. Size radios are visually hidden in their labels: click the `label`, never `check()` the radio (it waits forever).
- `palette.spec.ts` runs in both passes. The trigger is a magnifier at the top of the rail (step 47 slice 1; "Ctrl K" text under it, the palette opens centred near the top); locate it by its name ("Cerca o esegui, scorciatoia Ctrl K"), the dialog as `getByRole('dialog', { name: 'Comandi' })`, the field as its `combobox`, groups by `role="group"` named by heading (Vai a, Azioni). It covers: the trigger's place in the rail, click and Ctrl+K open it and Escape returns focus to the pill, a click on the veil closes, the grow (script and CSS animations inside the dialog above zero a few frames after the click; none with reduced motion, plus none for the page slide, which only the component's own reduced branch stops), loading and generic error of the registry (the registry is fetched in a batch with `health` and `layout.get`, so route `**/trpc/*registry.list*`; the query retries with a back-off, wait up to 20 s), a failing action, Backspace and Escape leaving a form page, pill contrast and the open palette inside the screen in ink and paper at 1920 and 3840, Vai a with a `window` marker that survives navigation, forms, danger only through the hold.
- `palette.spec.ts`: Escape leaves a page first, so a test that ends on a form presses it twice.
- `palette.spec.ts`: Wait for the field to be focused (or an option visible) before pressing Enter: the registry loads on open, and a `fill` before the dialog is ready was a real race. No real desktop command is used.
- `palette.visual.spec.ts`: The palette places itself when it opens, so a spec that changes the viewport closes it first and opens it again (resizing an open palette left it off centre by a varying amount, and the first baselines caught that and the unfocused form: fixed 2026-11-10).
- `desk.visual.spec.ts`: Deck tests navigate to Sistema for the Luce tile. Desk visual captures set reduced motion before load and wait for the media icon to settle: its Web Animations can otherwise race screenshot capture.
- `lavoro.spec.ts`: `--repeat-each` reuses one fake server, so a spec that changes server state is not idempotent under it (the lavoro undo spec passed 3 times and then failed 17 times for that reason); to repeat such a spec, start a process per run.
- `devices.spec.ts`: Mocking a tRPC query with `page.route` breaks when the page batches it with others (`/trpc/a,b`): the single-result answer replaces the whole batch. Use `answerQueries` in `tests/devices.spec.ts` (fetches the real batch, swaps only the mocked results).
- A radio started in a spec runs on for every later file in the process (files run alphabetically in a shard) unless the spec calls `music.stop` (Ferma, since 2026-11-17; the last test of `music.spec.ts` does). Radio cases live in `music.spec.ts`: the ball-over-Musica-with-radio check moved there from `activity.spec.ts` after it broke `design.spec.ts` artwork and the Media baselines in one shard. `ballOf` and `underBall` are shared in `tests/ball.ts`.
- `themes.spec.ts`: rows are `fieldset li`; rows, swatches and presets are labels around visually hidden radios, so click the label (`pick` in the spec, `chooseTheme` in `themes.ts`). The contrast and hue sliders are native ranges inside `Slider`: `focus()` plus `Home` or `End`.
- `mail.spec.ts`: a message's list button is `messageRow(page, text)` (`li button[aria-pressed]`): the hover actions of a row carry the subject in their names, so a bare name regex is ambiguous. The account switch is `getByRole('toolbar', { name: 'Account' })` (ButtonGroup). Paging is tested by fulfilling `mail.inbox` and reading the cursor from the batched URL (`workOffset`). Holds are `focus()` plus Space for 1 s. A failed send uses `/__fake/mail {fail:true}` (reset in `finally`); archive tests undo through Annulla so the shared fake keeps its inbox.
- `calendar.spec.ts`: A day cell is a button under its chips: click it in its corner (`click({ position: { x: 20, y: 6 } })`), the middle of a busy cell is a chip that opens the event. `calendar.spec.ts` seeds four events on the 19th: at 1920 the cell shows one chip and "+3". A new rail entry changes the example-pass baselines too (`desk-devices-tabs`, `desk-example-4k`, `desk-system-example`): rewrite them with `HUB_EXAMPLE_MODULES=1`.

## State a spec must put back

- `palette-regressions.spec.ts`: Its layouts are reset in finally.
- `settings.spec.ts`: Both restart tests switch a module with `saveSwitch` and put it back in `finally` through the API (`ensureOn`): the fake keeps the file between tests of a process, so a dead test must not leave a module off.
- `deck.spec.ts`: clear `hub.deck.page` and `hub.theme` in `finally`. `pomodoro.spec.ts`: restore `pomodoro.configure` fixture durations. `system.spec.ts`: restore the monitor in `finally`. `notes.spec.ts`: remove notes in `afterEach`. `mail.spec.ts`: reset the mail fake in `finally` and undo archives.
- The fake desktop is one shared state (default sink, play status) per Playwright process, and tests in a process run one at a time (`workers: 1`); parallelism is several processes, each with its own fake desktop (see "Parallel run"). A test that changes it puts it back; `deck.spec.ts` also runs `restoreDesktop` (`tests/desktop.ts`) in `afterEach`, so a test that dies halfway does not make the next ones fail. A second client is a plain HTTP call through the `pc` fixture (`playPause(pc)`). A test that pairs a device with `pairDevice(pc, name)` removes it with `revokeDevices(pc, name)` in `finally`. Wrong pairing codes are rate limited per address (5 a minute, and every browser here is `127.0.0.1`): a spec may send a few, not a loop.
- `activity.spec.ts`: Its `afterEach` stops Pomodoro, cancels the job and restores the player. The private Lavoro spec checks the collection and Pareri rows by role and name.
