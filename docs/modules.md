# Writing a module

Moved out of the root `AGENTS.md` to keep it short; the rules here are as binding as the ones there.

A module is one folder with `server.ts` (required) and `ui.tsx` (optional). Public modules live in `apps/server/src/modules/<name>/` and are listed in `apps/server/src/modules.ts`; private ones are a folder in the gitignored `modules.local/` and are discovered at startup, no tracked file changes. `modules.example/hello/` is the working reference (state, live updates, an action, a file round trip, a widget, a zone page, a section on the Lavoro zone and a deck tile). <!-- guard-private: allow Repository-local module directory -->

- **Server** (`server.ts`): `export default defineModule({ name, config?, zones?, create })` from `apps/server/src/core/module.ts`. That file also exports `z` and `TRPCError`: a module folder cannot resolve `zod` or `@trpc/server`. `create({ db?, run, fetch, log, config })` returns `{ router, close? }`; live hubs and services are built inside it and closed in `close`. `config` is the zod slice: public modules read `config.<name>`, private ones `modules.<name>` in `config.local.json`. Names match `^[a-z][a-z0-9-]{0,39}$`; a name or zone that collides, a bad config or a throwing factory skips that module with a log line (no payload) and the server still starts.
- **Checks**: private modules are outside every workspace, so `scripts/check-modules.ts` covers them (`pnpm check:modules [name]`, and `pnpm check` runs it for all). For each folder of the private root with a `server.ts` it checks formatting with Prettier, runs every `*.test.ts` under it with `node --test` and typechecks the folder with `scripts/tsconfig.modules.json` (the server's Node settings plus JSX and the web `@/` alias). It prints module names and counts, and the failure output in full only when something fails; an unknown name exits 1 and lists the modules found; with no private root or an empty one it prints that and exits 0, so a fresh clone behaves as before. `HUB_MODULES_ROOT` overrides the root, as for discovery. `pnpm format:modules [name]` formats the selected private module or all modules; generated Drizzle files stay ignored. The private check bypasses Git ignore rules using `.prettierignore`, while oxlint still skips private code. A test inside a private module imports the engine by relative path (`../../apps/server/src/...`), like its `server.ts`. A module `ui.tsx` imports the web app's packages by their bare name (`@tanstack/react-query`, `@phosphor-icons/react`, `motion/react`, `rough-notation`); `tsconfig.modules.json` maps each one to `apps/web/node_modules` for the typecheck. Never import from a `node_modules` path (`../../apps/web/node_modules/...`, `.pnpm/...`): Vite then loads a second copy beside the pre-bundled one, its React Query context is empty ("No QueryClient set"), and the page breaks (16l review). A package not yet mapped gets a line in `tsconfig.modules.json` and an alias in `apps/web/vite.config.ts` (the build resolves from the private folder, which has no `node_modules`).
- **E2E**: a private module with an `e2e/` folder is tested with Playwright via `pnpm test:e2e:private [name]` (`scripts/test-e2e-private.ts`), which sets `HUB_E2E_PRIVATE` to the module's `e2e/` folder and runs the private desk project against its `root/`. `pnpm test:e2e` (so `pnpm verify`) runs the private pass next to the example pass, after the public pass, when any private module has an `e2e/` folder; with no private root or no `e2e/` folders it prints that and exits 0. Private specs assert by role, name and state only, never screenshot baselines.
- **Storage**: a public or discovered module that keeps data declares `migrations: fileURLToPath(new URL('./drizzle', import.meta.url))` in `defineModule`, the absolute path of its own Drizzle folder, and `create` gets its own SQLite file as `deps.db`, migrated (WAL, foreign keys) before it runs. The file is `<folder of the core database>/modules/<name>.db`, so `~/.local/state/hub/modules/<name>.db` in real use and in memory when the core database is `:memory:` (tests and the e2e fake write no file). Back the `modules/` folder up with `hub.db`. A discovered module never gets the core database: with no `migrations` its deps have no `db` (the type says so), and `coreDb: true`, which gives the core one to the public modules that need it, is refused in discovery. A migration that throws, a missing or relative folder or a file that cannot be opened skips only that module, with the usual payload-free log line. The database closes with the server, after the module's own `close`. The module keeps `schema.ts`, `drizzle.config.ts` and the generated `drizzle/` in its folder (`modules.example/hello/` is the reference); import `sqliteTable`, `integer`, `eq` and the rest from `apps/server/src/core/module-db.ts`, because a module folder cannot resolve `drizzle-orm` (the same reason `z` comes from `module.ts`). Generate with `pnpm --filter @hub/server exec drizzle-kit generate --config ../../modules.local/<name>/drizzle.config.ts`: the config path is relative to `apps/server`, and `schema` and `out` inside it must be absolute (built from `import.meta.url`) because drizzle-kit resolves them against the working directory, not the config file. Never edit a migration that has run; generate a new one. <!-- guard-private: allow Repository-local module directory -->
- **HTML**: a module that scrapes a page or cleans markup imports `parseHTML` from `apps/server/src/core/module-html.ts` (linkedom, exact version in `@hub/server`), because a module folder cannot resolve `linkedom` (the same reason as `z` and drizzle). `parseHTML(html).document` is typed as a DOM `Document`, so code written against the DOM API is shared with the browser, where `new DOMParser().parseFromString(html, 'text/html')` gives the same shape; linkedom's own `DOMParser` is not re-exported because its type does not assign to `Document`. Pass shared code an inert document, never the page's own.
- **Files**: an action takes `{ fileId }` and reads it with `ctx.files.get/read`; it returns `ctx.files.put(bytes, { name, mime })`. Upload is `POST /files`, download `GET /files/:id`, both behind the same loopback-or-token check as tRPC; ids are opaque and expire after an hour. Downloads are attachments; `?inline=1` opts PDFs into inline display. Never accept an unrestricted client path: Study resolves relative PDF paths against configured material folders and checks their real paths remain inside them.
- **Focus history**: `deps.focusHistory.minutesByTag(prefix)` reads completed focus minutes grouped by tag from the core database, including for modules with their own database. `subscribe` reports completed tagged focuses; unsubscribe when the module closes. Pomodoro accepts an optional tag on start and does not interpret it.
- **Web** (`ui.tsx`): `export default { name, copy, widgets?, todayItems?, zone?, sections?, deck? } satisfies ModuleUI` (`apps/web/src/lib/module-ui.ts`). Widgets are for Panoramica, the one widget board. `todayItems` is a component or list of components, each a short line with an optional link, rendered in module order in Oggi when the module is on. `zone: { id, label, icon, page }` adds a rail entry and a page the module lays out (its id is its path, `/desk/<id>`, so never a built-in page's path such as `studio`, `lavoro`, `messaggi` or `settings`: the server refuses the zone (`builtinZones` in `apps/server/src/modules/layout/router.ts`) and the web skips it with a warning); `sections: [{ zone, id, label, component }]` add a tab to any zone page after its own tabs, including the built-in Lavoro (`work`) and Messaggi (`messages`) zones, which exist only while a module gives them a section (see `apps/web/AGENTS.md`). Call the server with `createModuleClient<typeof definition>(name)` and a type-only `import type definition from './server.ts'`: inputs and outputs are inferred from the module's own router. Copy is a plain Italian object in the module (private modules cannot join the tracked Paraglide settings).
- A zone or section can set `fill: true` to receive the available desk height and own its scroll regions; see “Desk layers and scrolling” in `apps/web/AGENTS.md`.
- **Discovery points** are the only tracked files that may reach `modules.local/`: `apps/server/src/core/discovery.ts`, `apps/web/src/lib/modules.ts` (through the `@hub-private-modules` Vite alias; it must not start with `/`, or Vite joins it to the project root and never applies the alias) and `apps/web/src/index.css` (a Tailwind `@source` for the private root: Tailwind scans only `apps/web`, and the module folder is outside it and gitignored, so a utility used only by a private module's `ui.tsx` generated no CSS, silently; a clone without the folder builds as before). `pnpm guard` fails on any other tracked path into it, stylesheets included, and checks the folder stays ignored. <!-- guard-private: allow Repository-local module directory -->
- **Private repository**: `modules.local/` may be its own git repository (local, or with a private remote the owner adds; never named in tracked files). The outer repo ignores the whole folder, and discovery tries only folders whose name is a valid module name, so `.git` and tool folders are skipped silently. Commit it in the same review as the public commit, with its own message. <!-- guard-private: allow Repository-local module directory -->
- **Example mode**: `HUB_EXAMPLE_MODULES=1 pnpm dev` loads `modules.example/`. `pnpm test:e2e` runs the suite twice (the public pass in two shards, then the example pass); the example pass loads `modules.example/` through `HUB_MODULES_ROOT`, the same path a private module takes.

Skeleton (`modules.local/<name>/server.ts`): <!-- guard-private: allow Repository-local module directory -->

```ts
import { defineModule, z } from '../../apps/server/src/core/module.ts';
import { protectedProcedure, router } from '../../apps/server/src/core/trpc.ts';

export default defineModule({
  name: 'notes',
  config: z.object({ title: z.string().default('Note') }).default({ title: 'Note' }),
  create({ config }) {
    return {
      router: router({
        state: protectedProcedure.query(() => ({ title: config.title })),
      }),
    };
  },
});
```

- **Impostazioni** (settings page): a module's config can be edited from the desk and the module switched off. The form is drawn from `settingsSchema` (or `config` when absent; a module whose config is `z.unknown()` has no form). Mark a secret field `.meta({ secret: true })`: it is never sent to the page and can only be replaced. Label every field and object in Italian with `.meta({ title, description, unit })` (title 1 to 3 words, description one sentence that says what an empty value means; a field without `title` shows its key), and give string enums or integer choices `optionLabels: { <value>: '<label>' }`. Shapes and their controls: string, number (stepper with `unit`, `minimum`/`maximum`), boolean, enum or labelled integer (select), array of those (multi-select), array of strings (tags), `z.record(string, number)` and `z.record(string, string[])` (rows of key and value), array of flat objects (a table); plain objects become titled sections; anything nested deeper or a union is a JSON block under Avanzate, so shape a config as these where you want a control. An unset field shows its schema `default` ("Predefinito") and saving never writes it. A module in `modulesOff` (top level of the config file) is imported but never created: no database file is opened, no timer or route starts, and its data stays for when it is switched back on.
