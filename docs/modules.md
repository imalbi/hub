# Writing a module

Moved out of the root `AGENTS.md` to keep it short; the rules here are as binding as the ones there.

A module is one folder with `server.ts` (required) and `ui.tsx` (optional). Public modules live in `apps/server/src/modules/<name>/` and are listed in `apps/server/src/modules.ts`; private ones live in the gitignored `modules.local/` and Git catalog ones in `modules.installed/` (cloned repos in `modules.repos/`), both discovered at startup in order (`modules.local/` wins on name collision), no tracked file changes. `modules.example/hello/` is the working reference (state, live updates, an action, a file round trip, a widget, a zone page, a section on the Lavoro zone and a deck tile). <!-- guard-private: allow Repository-local module directory -->

- **Server** (`server.ts`): `export default defineModule({ name, config?, zones?, create })` from `apps/server/src/core/module.ts`. That file also exports `z` and `TRPCError`: a module folder cannot resolve `zod` or `@trpc/server`. `create({ db?, run, fetch, log, config })` returns `{ router, close? }`; live hubs and services are built inside it and closed in `close`. `config` is the zod slice: public modules read `config.<name>`, private ones `modules.<name>` in `config.local.json`. Names match `^[a-z][a-z0-9-]{0,39}$`; a name or zone that collides, a bad config or a throwing factory skips that module with a log line (no payload) and the server still starts.
- **Checks**: private and installed modules are outside every workspace, so `scripts/check-modules.ts` covers them across `defaultModuleRoots` (`pnpm check:modules [name]`, and `pnpm check` runs it for all). For each folder with a `server.ts` (earlier root wins on collision) it checks formatting with Prettier, runs every `*.test.ts` under it with `node --test` and typechecks the folder with `scripts/tsconfig.modules.json` (the server's Node settings plus JSX and the web `@/` alias). It prints module names and counts, and the failure output in full only when something fails; an unknown name exits 1 and lists the modules found; with no roots or empty ones it prints that and exits 0, so a fresh clone behaves as before. `HUB_MODULES_ROOT` overrides the roots as a single root, as for discovery and isolated web builds. `pnpm format:modules [name]` formats the selected discovered module or all modules; generated Drizzle files stay ignored. The check bypasses Git ignore rules using `.prettierignore`, while oxlint runs on discovered modules too. A test inside a discovered module imports the engine by relative path (`../../apps/server/src/...`), like its `server.ts`. A module `ui.tsx` imports the web app's packages by their bare name (`@tanstack/react-query`, `@tanstack/react-router`, `@trpc/tanstack-react-query`, `@phosphor-icons/react`, `motion/react`, `rough-notation`); `tsconfig.modules.json` includes Vite client declarations for CSS and `ImportMeta`, and maps each shared package to `apps/web/node_modules` for the typecheck (mapping `@trpc/tanstack-react-query` to `./dist/index.d.mts` so TypeScript uses ESM declarations matching `@trpc/client`), and `apps/web/vite.config.ts` aliases them so the build uses the single pre-bundled instance. Never import from a `node_modules` path (`../../apps/web/node_modules/...`, `.pnpm/...`): Vite then loads a second copy beside the pre-bundled one, its React Query context is empty ("No QueryClient set"), and the page breaks (16l review). An additional shared web package not yet mapped gets a line in `tsconfig.modules.json` and an alias in `apps/web/vite.config.ts` (shared libraries must resolve to the same app instance).
- **Owned npm packages**: a catalog module may ship its own `package.json` and mandatory `pnpm-lock.yaml`. Import owned dependencies by bare name from that module; keep React, TanStack and tRPC on the shared exports/aliases above. Catalog source must contain no `node_modules`, symlinks or nested Git folders. Install/update runs `pnpm install --dir <staging> --ignore-scripts --frozen-lockfile --ignore-workspace` with a two-minute timeout before swapping the installation. The workspace flag prevents pnpm from installing the ancestor Hub workspace. Failure preserves the prior module and pending state; removal preserves its database. Checks ignore dependency folders.
- **Dependencies and capabilities**: declare `provides?: string[]`, `requires?: string[]` and `optional?: Record<string, string>` on both `defineModule` and the v1 catalog entry. Keys are module/capability names; optional values explain the integration in Italian. Discovery orders providers before consumers, skips hard cycles or absent/disabled/failed requirements, and allows missing optional integrations. `create` receives `capabilities` (`register`, `get`, `has`, `list`, re-exported from `core/module.ts`); extend `CapabilityMap` with the actual typed contract (for example `mail`: `MailCapability`). Only a successful factory publishes its registrations. Duplicate providers fail. A direct `defineModule(...).create(...)` caller may omit the registry and receives an empty one. Catalog badges and install/update checks use live modules/capabilities: apply a newly installed provider before installing its consumer. `minHubVersion` accepts a concrete minimum or semver range, checked against the root package version (currently 1.0.0).
- **HTTP routes**: return `routes(scope)` beside `router`/`close` to register relative Fastify routes under `/m/<module>/`. The scope enforces Host, Origin and paired-device/loopback auth; use bearer auth on paired-device requests. Vite proxies `/m`, and unknown module paths never return the SPA. A route that needs stricter permissions must check them itself.
- **E2E**: a private module with an `e2e/` folder is tested with Playwright via `pnpm test:e2e:private [name]` (`scripts/test-e2e-private.ts`), which sets `HUB_E2E_PRIVATE` to the module's `e2e/` folder and runs the private desk project against its `root/`. `pnpm test:e2e` (so `pnpm verify`) runs the private pass next to the example pass, after the public pass, when any private module has an `e2e/` folder; with no private root or no `e2e/` folders it prints that and exits 0. Private specs assert by role, name and state; visual baselines belong under that module’s `e2e/__screenshots__/`, never in public tracked snapshots.
- **Storage**: a public or discovered module that keeps data declares `migrations: fileURLToPath(new URL('./drizzle', import.meta.url))` in `defineModule`, the absolute path of its own Drizzle folder, and `create` gets its own SQLite file as `deps.db`, migrated (WAL, foreign keys) before it runs. The file is `<folder of the core database>/modules/<name>.db`, so `~/.local/state/hub/modules/<name>.db` in real use and in memory when the core database is `:memory:` (tests and the e2e fake write no file). The daily backup copies every open module database with `hub.db` (`docs/backup.md`); a module registers nothing for it. A discovered module never gets the core database: with no `migrations` its deps have no `db` (the type says so), and `coreDb: true`, which gives the core one to the public modules that need it, is refused in discovery. A migration that throws, a missing or relative folder or a file that cannot be opened skips only that module, with the usual payload-free log line. The database closes with the server, after the module's own `close`. The module keeps `schema.ts`, `drizzle.config.ts` and the generated `drizzle/` in its folder (`modules.example/hello/` is the reference); import `sqliteTable`, `integer`, `eq` and the rest from `apps/server/src/core/module-db.ts`, because a module folder cannot resolve `drizzle-orm` (the same reason `z` comes from `module.ts`). Generate with `pnpm --filter @hub/server exec drizzle-kit generate --config ../../modules.local/<name>/drizzle.config.ts`: the config path is relative to `apps/server`, and `schema` and `out` inside it must be absolute (built from `import.meta.url`) because drizzle-kit resolves them against the working directory, not the config file. Never edit a migration that has run; generate a new one. <!-- guard-private: allow Repository-local module directory -->
- **HTML**: modules that scrape a page or clean markup declare `"linkedom"` directly in their own `package.json` + `pnpm-lock.yaml` (see "Owned npm packages" above) and import `{ parseHTML } from 'linkedom'`. `parseHTML(html).document` is typed as a DOM `Document`, so code written against the DOM API is shared with the browser, where `new DOMParser().parseFromString(html, 'text/html')` gives the same shape; linkedom's own `DOMParser` is not re-exported because its type does not assign to `Document`. Pass shared code an inert document, never the page's own.
- **Files**: an action takes `{ fileId }` and reads it with `ctx.files.get/read`; it returns `ctx.files.put(bytes, { name, mime })`. Upload is `POST /files`, download `GET /files/:id`, both behind the same loopback-or-token check as tRPC; ids are opaque and expire after an hour. Downloads are attachments; `?inline=1` opts PDFs into inline display. Never accept an unrestricted client path: Study resolves relative PDF paths against configured material folders and checks their real paths remain inside them.
- **Focus history**: `deps.focusHistory.minutesByTag(prefix)` reads completed focus minutes grouped by tag from the core database, including for modules with their own database. `subscribe` reports completed tagged focuses; unsubscribe when the module closes. Pomodoro accepts an optional tag on start and does not interpret it.
- **Web** (`ui.tsx`): `export default { name, copy, widgets?, todayItems?, todayHeader?, mediaUpcoming?, settingsHeader?, activities?, calendarItems?, daySummary?, deviceRows?, systemRows?, zone?, sections?, deck? } satisfies ModuleUI` (`apps/web/src/lib/module-ui.ts`). Widgets are for Panoramica, the one widget board. `todayItems` is a hook or list of hooks returning short lines with optional links, rendered in module order in Oggi when the module is on; `todayHeader` is an optional component beside the clock (`look: "block" | "caption"`, `align?: "start" | "end"`); the first active contributor wins and no column is reserved without one. `todayColumn` is one component for the middle column of Oggi (a bottom aligned stack of cards, used by the post-its). `activities` is a hook or list of hooks (`ModuleActivityHook`: returns `{ id, label, detail, progress?, href }`, or null when nothing runs) for the "Attività in corso" ball: each non-null result is one row of its panel, a link to `href`, while the module is on (do not name the variable that holds a hook `use`); `deviceRows` is a component or list of components, each one row (`DeviceRow` from `apps/web/src/components/device-row.tsx`: name, state, controls, optional full-width `below`) in the "Collegati a questo PC" panel of Dispositivi, rendered in module order while the module is on; a row may return null until it has data, and with no row declared the panel is not drawn (`modules.example/hello/` has one). `systemRows` is the same for the "Questo PC" list of Sistema (after Webcam and the configured monitors, before Alimentazione; a row that returns null leaves no gap). A module that fails to load (for example a required config field missing, as `modules.airplay.command`) is not on, so it shows no row, tile or palette action. `deck.at` inserts the tiles at an index of the target page (`page: 'desk'` means Scrivania). Without `at`, a module's tiles go together to the last page with room for all of them (12 rendered tiles a page), before Sistema's three holds; if none has room, a new page is added. `zone: { id, label, icon, page }` adds a rail entry and a page the module lays out (its id is its path, `/desk/<id>`, so never a built-in page's path such as `lavoro`, `messaggi` or `settings`: the server refuses the zone (`builtinZones` in `apps/server/src/modules/layout/router.ts`) and the web skips it with a warning); `sections: [{ zone, id, label, component }]` add a tab to any zone page after its own tabs, including the built-in Lavoro (`work`) and Messaggi (`messages`) zones, which exist only while a module gives them a section (see `apps/web/AGENTS.md`). Call the server with `createModuleClient<typeof definition>(name)` and a type-only `import type definition from './server.ts'`: inputs and outputs are inferred from the module's own router. Copy is a plain Italian object in the module (private modules cannot join the tracked Paraglide settings).
- **Availability**: `ModuleUI.useAvailable` owns configured/usable state; `usePending` and `pendingPage` optionally preserve a zone's loading geometry. `ModuleAvailabilityProvider` mounts a stable hook layer per module. Hooks can read `useModuleEnabled` from `lib/module-enabled.ts` to disable requests when off; never import the UI registry back into these hooks. The shell combines enabled state and availability without domain imports.
- **Day line**: today's timed `calendarItems` also appear on the Panoramica and Studio day lines. `daySummary` returns one short string or null for the Panoramica summary. Widgets can import `Readout` and `Ticks` from `apps/web/src/components/`; `Panel` gives widget titles and actions the mono label role automatically. See `modules.example/hello/ui.tsx` for a calendar item and a readout.
- **Records for the palette** (step 64): `records?: RecordSource | RecordSource[]` in `ModuleUI`. A `RecordSource` is `{ id, label, search(query, signal), allHref? }` (`apps/web/src/lib/module-ui.ts`): `search` is a plain async function that calls the module's own typed client and returns `{ total, rows }` with `rows` of `{ id, title, detail, badges?, href }`; the palette keeps 3 rows, shows `total` and, with `allHref(query)` and more matches than rows, "Vedi tutti in <zona>". The match happens on the server, in a query that already cuts to 3 and counts (`loopbackProcedure`, or the module's own list level when that is stricter: record names never reach a paired phone); never filter a whole list in the browser. The source `id` is permanent (step 71 stores it next to a record id in post-its): name it for what it holds. Taken so far: `study-days` (Studio days, `study.searchRecords`), `mail-messages` (catalog `mail` module, `mail.searchRecords`), `hello-greetings` (the example module), `lavoro-postings` and `lavoro-applications` (catalog `lavoro` module, `lavoro.searchRecords.postings` and `.applications`). `href` goes through `router.history.push`, so it may carry search params the page validates (`mail` uses `?tab=mail&subject=&message=<account>:<id>`, `lavoro` `?job=<key>`).
- **Post-it references** (step 71): a source whose records can receive post-its implements `get(id, signal)` returning its current `RecordRow` or null. A page showing one record calls `setCurrentRecord({ source, id, title })` and clears it on cleanup; `RecordNotes` shows that record's open post-its and opens capture for it. Source ids are persisted and must never be renamed. Cards resolve the current href with `get` and show the stored title as plain text when the source or record is unavailable. `mail` has no `get` until its record identity is decided.
- `mediaUpcoming` contributes optional content below the large core Media widget; the module owns its queries and empty state.
- `PageTab.dayLine` supplies a zone header component. `fallback: true` hides a core tab when active modules contribute sections to that zone; without contributors the core tab remains available. A zone with `ownTabs: true` supplies its own first tab.
- A zone or section can set `fill: true` to receive the available desk height and own its scroll regions; `float` lets the section float over the desk background; see “Desk layers and scrolling” in `apps/web/AGENTS.md`.
- **Discovery points** are the only tracked files that may reach `modules.local/`, `modules.installed/`, or `modules.repos/`: `apps/server/src/core/discovery.ts`, `apps/web/src/lib/modules.ts` (through the `@hub-private-modules` and `@hub-installed-modules` Vite aliases; neither may start with `/`, or Vite joins it to the project root and never applies the alias) and `apps/web/src/index.css` (Tailwind `@source` directives for both module roots: Tailwind scans only `apps/web`, and the module folders are outside it and gitignored, so a utility used only by a discovered module's `ui.tsx` would otherwise generate no CSS silently; a clone without those folders builds as before). `pnpm guard` fails on any other tracked path into `modules.local/`, `modules.installed/`, or `modules.repos/`, stylesheets included, and checks all three stay ignored. <!-- guard-private: allow Repository-local module directory -->
- **Private repository**: `modules.local/` may be its own git repository (local, or with a private remote the owner adds; never named in tracked files). The outer repo ignores the whole folder, and discovery tries only folders whose name is a valid module name, so `.git` and tool folders are skipped silently. Commit it in the same review as the public commit, with its own message. <!-- guard-private: allow Repository-local module directory -->
- **Example mode**: `HUB_EXAMPLE_MODULES=1 pnpm dev` loads `modules.example/`. `pnpm test:e2e` runs the suite twice (the public pass in two shards, then the example pass); the example pass loads `modules.example/` through `HUB_MODULES_ROOT`, the same path a private module takes.

Skeleton (`modules.local/<name>/server.ts`): <!-- guard-private: allow Repository-local module directory -->

```ts
import { defineModule, z } from '../../apps/server/src/core/module.ts';
import { protectedProcedure, router } from '../../apps/server/src/core/trpc.ts';

export default defineModule({
  name: 'notes',
  config: z.object({ title: z.string().default('Note') }).default({ title: 'Note' }),
  create({ config }) {
    return {
      router: router({
        state: protectedProcedure.query(() => ({ title: config.title })),
      }),
    };
  },
});
```

- **Impostazioni** (settings page): a module's config can be edited from the desk and the module switched off. `ModuleUI.settingsHeader` can add controls before the schema form and replace its draft through `onSelect(value)` (for example a location picker); it is shown only while the server module is on. The form is drawn from `settingsSchema` (or `config` when absent; a module whose config is `z.unknown()` has no form). Mark a secret field `.meta({ secret: true })`: it is never sent to the page and can only be replaced. Label every field and object in Italian with `.meta({ title, description, unit })` (title 1 to 3 words, description one sentence that says what an empty value means; a field without `title` shows its key), and give string enums or integer choices `optionLabels: { <value>: '<label>' }`. Shapes and their controls: string, number (stepper with `unit`, `minimum`/`maximum`), boolean, enum or labelled integer (select), array of those (multi-select), array of strings (tags), `z.record(string, number)` and `z.record(string, string[])` (rows of key and value), array of flat objects (a table); plain objects become titled sections; anything nested deeper or a union is a JSON block under Avanzate, so shape a config as these where you want a control. An unset field shows its schema `default` ("Predefinito") and saving never writes it. A module in `modulesOff` (top level of the config file) is imported but never created: no database file is opened, no timer or route starts, and its data stays for when it is switched back on. An optional `setupNote: (config) => string | undefined` (Italian, like a schema `title`) puts a short note and a muted dot on the module's row while it is on and still unusable, e.g. `'manca la città'` for weather without a place; a note that throws is none.

Modules can import `ollamaChat` and `OllamaError` from `core/module.ts` for the shared loopback Ollama chat transport. Supply `numCtx` explicitly and use `llmGate` for model work.
